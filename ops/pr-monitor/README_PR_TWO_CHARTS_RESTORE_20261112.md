# PR Monitor · оба графика восстановлены (12.11.2026)

После исправления зависания iPhone и главного `/` на LIVE остались только KPI/этапы. В прямом HTML, собранном из старого `legacy.html`, **отсутствовало подключение `pr-trends.js` и `pr-trends.css`**, поэтому DOM первого оригинального графика `#hh-pr-trends` вообще не создавался. Модуль `pr-compact-top.js` размещал графики лишь после появления несуществующего в этом HTML `#hh-pr-merge-speed`; графики не переносились наверх. Второй `pr-merge-velocity-ui.js` монтировался, но создавал стили внутри `<style>`, который блокировался текущим строгим CSP.

## Исправление

- Восстановлены оригинальные `pr-trends.js` (12,299 байт) и `pr-trends.css` (2,881 байт) из работающего неизменённого артефакта Vercel. Они отображают **Новые PR / Merge / CI по часам** и сохраняют исходные селекторы и значения. У оригинала остаётся собственный ограниченный клиентский 15-минутный refresh GitHub: это не новый серверный cron, но источник запросов, который впоследствии можно объединить с существующим read-only API.
- Оригинальный `pr-merge-velocity-ui.js` сохраняет график **задержек PR → Merge** с выбором периода и фактическим read-only `/api/pr-stage-timeline`; код/данные графика не заменяются. Его прежний CSS из заблокированного встроенного блока перенесён в `pr-graphs-restore.css`, совместимый с `style-src 'self'`.
- Независимый `pr-graphs-restore.js` помещает оба уже созданных исходных DOM-элемента в `#hh-pr-top-graphs` прямо после заголовка страницы, на мобильном один под другим. Восстановление не зависит от `#hh-pr-merge-speed`, не дублирует SVG и не добавляет запросов, таймеров или CI. Поздний mount графика обрабатывается MutationObserver, который отключается после появления обоих.
- `pr-monitor.html` и `index.html` одинаковы, сохранили оригинальный dashboard, `data-pr-stage-only` и полный **Created → CI → Merge → LIVE** под графиками, а также другие блоки. Не возвращать загрузочный stub или HTML meta redirect.

Проверки исходников: синтаксис JS, наличие обоих графиков и их стилей, сохранение полного пути, порядок загрузки перед recovery, отсутствие новых запросов/таймеров в DOM-organizer, перенос исходных DOM узлов и поздняя инициализация. Команда: `node --test ops/pr-monitor/tests/pr-two-chart-restore.test.cjs`.
