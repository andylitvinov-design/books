# Holistic House · Video Director 2.0 — исполняемый алгоритм и план выпуска

**Дата:** 05.11.2026 · **Owner goal:** готовые персональные MP4 из утверждённых сценариев, а не только визуальный каталог.  
**Источник production:** `codex/public-book-library`; старый default `codex/bootstrap-books` не является сайтом.  
**Политики:** [PR One Publish v1](https://github.com/andylitvinov-design/ai-projects-brain/blob/main/systems/pr-one-publish-standard.md), `AGENTS.md`, `docs/operations/CI_RELEASE_POLICY.md`.  
**Статус:** реализация и тесты сначала в защищённом PR; публикация LIVE требует отдельных доказательств, не следует из документа.

## 1. Инварианты модели

Ветка контента: **categoryId → subcategoryId → topicId → meaningAxisId → motifId → filmScenarioId**.  
Ветка человека: **currentStateId → desiredStateId + optional intensity / energy / activation / feltSafety → эмоциональный допуск → стратегия**.  
Точка объединения: **подтверждённая идея → сценарный шаблон → четыре смысловых фазы → SceneScript → реальная видеотека → Canvas/MediaRecorder → проверенный файл**.

MeaningAxis (зачем) отличается от EmotionalAxis (какое переживание → какое переживание). Motif (через какой образ) отличается от FilmScenarioTemplate (какой тип события), EmotionalScenario (какая динамика), SceneScript (какие конкретные кадры) и Asset (какой реальный MP4). Не хранить всё в одном `scenarioId`. Авторы, психологический смысл и редактирование принадлежат пользователю; никакая эвристика не диагностирует, не обещает лечебный эффект и не отправляет личный текст/тесты в видеопровайдер.

Канон редакционных вариантов: 4 категории × 4 подкатегории × 4 темы = 64 темы; 8 смысловых осей; 4 предлагаемых мотива на ось; 4 сценарные альтернативы. Число 8192 — **редакторские пути**, не 8192 самостоятельных фильмов и не 8192 проверенных исходников. Сценарии по мотивам нуждаются в дальнейшей авторской проверке уникальности событий/выбора; совпадение ID или названия не является уникальной режиссурой.

## 2. Канонический вход

```json
{
  "topicId": "money-mindset",
  "meaningAxisId": "anchor",
  "motifId": "roots",
  "filmScenarioId": "money-mindset-s1",
  "emotional": {
    "currentStateId": "anxiety",
    "desiredStateId": "calm",
    "intensity": 8,
    "energy": 2,
    "activation": 7,
    "feltSafety": 3
  },
  "approvedIdeaId": "explicit-client-choice",
  "durationSeconds": 30,
  "aspect": "portrait",
  "locale": "ru",
  "excludedMotifs": [],
  "styleId": null
}
```

`approvedIdeaId` относится к более широкому Meaning Idea Engine; текущий автономный Scene Director может работать с отдельно подтверждённым STSE-переходом. Персональная формулировка не включается в публичный план автоматически. Отсутствующая энергия/активация не должна заполняться искусственным «5».

## 3. Шаги компилятора

### A. Normalize & validate
1. Проверить реальный `topicId` в опубликованном MyTube 4×4×4 и путь `meaningAxisId/motifId/filmScenarioId` по существующему реестру; не принимать ID вне зарегистрированной оси и мотива.
2. Получить эмоциональный вектор только из известной `STSE stateId → 8×8 cluster` связи. Неклассифицированное состояние — `UNMAPPED_EMOTIONAL_AXIS`, не придумывать смысл по ключевым словам.
3. Сохранить исключения, формат и выбранный язык. Нет подтверждённого эмоционального перехода — `NEEDS_EMOTIONAL_SELECTION`.
4. Не выводить клинический ресурс из `V×I`. Интенсивность, энергия, безопасность и активация — независимые входы.

### B. EmotionalEnvelope → StrategySequence
1. Если высокая интенсивность, низкая энергия, сильная активация или низкое чувство безопасности — сначала мягкая стабилизация/поддержка. Избегать форсированного конфликта, отрицательного «провала» и слишком резкого нарастания.
2. Восемь стартовых творческих стратегий: S01 стабилизация; S02 поддержка; S03 принятие; S04 прояснение; S05 воодушевление; S06 мобилизация; S07 интеграция; S08 обновление.
3. Составить четыре сценарные фазы с `strategyId`, `startT`, `endT`, `targetTags`. В конкретном ролике допустима последовательность стратегий, а не одна стратегия на весь фильм.
4. Выдать `emotionalEnvelope`, `whyCodes`, `reliefShapeIds`. Развитый рельеф V/A/S/E вводить только как авторскую динамику с явной маркировкой; не выдавать её за измеренную перемену самочувствия.

### C. Film scenario → четырехфазный смысл
Каждая фаза получает `beatIndex`, описание действия, `strategyId`, `role`, `targetVisualTags` и `emotionalTags`. Четыре смысловых этапа могут развернуться в большее число физических видеокадров. История не переписывается ради наличия привлекательного исходника.

### D. Shot budget & timeline
MVP: 10/15/20 секунд — 4 кадра; 30 секунд — 6; 60 секунд — 12. Кадр минимум 2 секунды; суммарная длительность равна точной длительности видео. Для ранних релизов оставляем исходный четырехкадровый пресет обратно совместимым, а 6/12 кадров включаем явным адаптивным путём. Плавный ритм задаёт редакционные переходы/темп; источники не растягивать под ограничения длительности.

### E. Media matching — жёсткие условия ДО рейтинга
1. Использовать **только** утверждённые same-origin MP4 с правами и доступным реальным файлом, физически известными `width/height/durationSeconds`. Проверять 16:9 и 9:16 по размерам видео, не по poster или CSS.
2. Дедупликация по физическому master/источнику/визуальной группе; новые crop ID одного ролика не считаются независимыми кадрами.
3. Источник обязан покрывать длину сцены без тайного повтора; запрещённые изображения и неразрешённые медиа исключать до ранжирования.
4. Рассчитать `match = stageTags*40 + emotionTags*5 + topicCandidateScore + motifMatch*50`, затем стабильная сортировка по оценке и ID. Эти веса — редакционная эвристика, не качество психотерапии.
5. Хотя бы одно соответствие тега каждой выбранной сцене обязательно; пользовательская замена проходит ту же проверку. Совпадение текстовых тегов **не подтверждает буквальное событие** сюжета, поэтому `depictedEventVerified=false`.
6. При недоступном физическом кадре вернуть `NEEDS_VERIFIED_MEDIA` с указанием `missingStage`, `missingShot`; не выдавать атмосферную анимацию за документальную съёмку. Отдельная символическая замена допускается только явно по выбору человека.

### F. Compile & render — один действующий рендерер
Подтверждённый `SceneScript` с `sceneId`, `beatIndex`, `strategyId`, `requiredTags`, `startSeconds`, `durationSeconds` и метаданными прав передаётся в существующий `compileFreeFilmPreset`. Из него формируется ровно тот `CinematicStoryboard`, который читает локальный Canvas/MediaRecorder/WebCodecs. Не строить параллельный backend. Адаптивный loader и source-clock проверяют все кадры перед экспортом. Встраивание эмоциональной скорости должно менять `speed` и воспроизводиться при записи; пользователь может её скорректировать.

Выход `READY_SYMBOLIC_LOCAL_RENDER` означает **возможность попытки браузерной сборки**, а не уже полученный MP4. `READY` не означает разрешение на публикацию или доказанное соответствие буквальным действиям. Фактический MP4 подтверждается только после завершения рендера, чтения готового файла, длительности, размеров, декодирования и воспроизведения.

## 4. Машина состояний

```text
DRAFT → PATH_VALIDATED → IDEA/EMOTION_CONFIRMED → SCRIPT_PLANNED
      → MEDIA_VERIFIED → READY_TO_RENDER → RENDERING
      → DECODE_VERIFIED → FILE_AVAILABLE

ANY_SELECTION_CHANGE → invalidate old render/timeline approval
MISSING_EMOTION → NEEDS_EMOTIONAL_SELECTION
UNKNOWN_PATH → INVALID_MEANING_PATH
NO_MATCHING_MP4 → NEEDS_VERIFIED_MEDIA (not fake success)
WRONG_ASPECT / REUSED_MASTER / DURATION_TOO_SHORT → BLOCKED
RENDER_DECODE_FAIL → EXPORT_UNAVAILABLE (no fake file)
```

## 6. Приёмочные тесты

- **Hierarchy:** все 64 темы / 8 осей / 4 мотива / 4 альтернативы; нельзя выбрать мотив другой оси.
- **Emotion:** высокий стресс + низкая энергия → мягкая S01/S02, не форсированный S06; отсутствующие поля остаются null.
- **Shot count:** 4/4/4/6/12 для длительностей 10/15/20/30/60, сумма всегда точная, минимум 2 секунды.
- **Media:** каждый кадр содержит уникальный `sourceMasterKey`, разрешённый MP4, обязательные теги, source length≥cut, физический aspect; запретный медиа/дубль блокируются.
- **Browser:** реальный click «Goal → Ideas → Montage → Generate Video» создаёт файл; каждый слот показывает правильный кадр и не замирает на старом декодированном изображении.
- **Regression:** исходный четырёхсценный редактор, свои фразы, voice/music, RU/EN/ES, iPhone navigation, consent/privacy не должны ломаться.
- **Protected release:** Core, профильный Specialist/WebKit, `hh-merge-check`, squash merge, затем Vercel production SHA и реальный E2E. CI green ≠ MP4 verified ≠ LIVE.

## 7. Что НЕ считать выполненным автоматически

Нет подтверждённых 8192 уникальных сценариев, 500×2 новых лицензированных видео, работающего платного AI-render-провайдера или клинически доказанной эмоциональной трансформации. Никаких новых платных сервисов, cron, деплой-планов, фальшивых видеоплейсхолдеров или незаметного профилирования. Каноническая видеотека/Cloudflare остаётся отдельной поставкой качества и прав. Недоступные физические сцены честно блокируют персональный фильм до поступления подходящих медиа.

**Фактические статусы при выпуске записывать независимо:** `SOURCE_READY`, `CI_GREEN`, `MERGED`, `VERCEL_READY_EXACT_SHA`, `IPHONE_MP4_E2E_PASS`.
