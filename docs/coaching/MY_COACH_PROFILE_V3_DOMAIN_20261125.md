# My Coach profile v3 domain contract — #5636 / #5588
This source slice adds a deterministic, question-bound reducer for the existing Director. It is not wired to production, does not add a database/table or start a model, and deliberately does not expose a new picker option yet. The server adapter must own the issued-question/event ledger and verified baseline, not trust a client-generated state or metadata. Introductory ID remains introductory; new internal proposed meaning ID meaning_axes_inner_growth. Separate outer current-only and selected desired values versus inner pair/missing-half flow; source IDs, actual quote/time, partial, skip, zero, correction and deterministic replay. Preserve existing historic inner protocol v1/v2. No false claim of full session algorithm or LIVE: parent #5633/#5635 and #5642 must first land/reconcile. Wire the existing Director and all provider paths, versioned protocol normalization, seven content sections, timebox, consent, actual profile/PDF, explicit new session registry and real signed-in mobile tests. Do not instantiate a second engine or parallel archive. Current reducer is a shared pure domain module, not a server trust boundary by itself.

## Priority and timebox handoff
The inner track asks for exactly one client-selected axis after numeric intake; outer accepts at most two complete canonical area labels, including compound localized names. The existing Director can issue an authorized `prioritize` ledger event at the end of the wheel timebox (intro minute 11 / inner minute 12), or upon an explicit client request. No remaining numbers are invented: the partial wheel stays partial, a single priority is captured for inner, and only selected desired slots are offered for outer. This event invalidates the old outstanding question and is replayed from trusted server evidence. It is not an autonomous timer or integration; actual Director, UI, persistence and authenticated E2E remain required.

## Archive proof adapter
New code: `coach-profile-archive-v3.mjs` replays only a server-owned event ledger, verifies source IDs, order, timestamps, question and actual transcript content; `my-coach-profile-proof.js` signs the normalized block and exact transcript prefix under owner/session/course/locale scope using the existing app encryption key's domain-separated operation hash. The receipt is not a provider or authentication grant. Before enabling v3, wire the server-issued ledger from existing Director, verify the receipt in both checkpoint and reviewed-save routes before storing in the existing encrypted record, and retain legacy inner v1/v2 readers. No browser-authored ledger may reach the signing helper. This draft adds executable adapter + tests, not an exposed API or production integration.

Each answer event now requires `questionTurnId` for the actual finalized canonical Director-issued assistant prompt, with matching question ID, exact text and ordering. Archive validation binds the prompt position and text as well as the answer. This is still a draft adapter; no provider/UI activation or trusted server ledger is implied.

## Existing archive integration (stacked on #5635)
Protocol normalization retains exactly one structured proof field (lifeBalanceCheckin or meaningAxesCheckin), checks track/course/locale/transcript and rejects mixing legacy ratings with new results. Both existing encrypted checkpoint and reviewed writers verify HMAC receipts, and checkpoint/finalize reject dropping or regressing a previous structured result. My Coaching, draft review and PDF render the same returned rows without invented zeroes. New course ID is recognized for archive compatibility only. No new database, exposed signing endpoint or paid service. Remains Draft until a trusted Director question/event issuance path, UI continuation, Node crypto/DB/browser and device tests are complete. Keep #5635 resume changes; do not merge this stack before its parent and actual functional integration.

## Private continuation preservation
Existing revision-bound private resume retains the server-issued v3 envelope (including its original protocol locale) through autosave and final PDF/archive. It cannot silently replace it with a legacy score or drop it after append; explicit erasure followed by a new logical report ID cannot reuse the old receipt. Existing local-only continuation stays in place; no new ratings or provider access are authorized by the receipt. Both v3 suites run in the existing coaching specialist gate. The Director issuance integration remains open; this patch does not activate a new public session path.

## Server step adapter (not an exposed endpoint)
`coach-profile-director-v3.mjs` implements first-party question issuance, server-stamped finalized answer events, stale-revision rejection, explicit priority/correction/close transitions, and replay into the existing archive. The caller must hold the acknowledged existing session/checkpoint lock and verify ownership, consent and opening completion. No caller-authored ledger can be accepted; no extra database/provider. The existing route/client wiring and provider delivery acceptance are still required. Also reuse the central protocol evidence veto and reject interrupted question prompts when producing or validating a signed profile. Native CI and signed-in mobile acceptance remain required.

## Delivery and HMAC acceptance gates
Issued profile questions are now pending, not transcript evidence. Only the trusted transport completion callback can commit the exact delivered prompt; interrupted attempts retain their observed text but are never rating evidence, and a new delivery attempt ID is required. Tests exercise stale and interrupted delivery. The existing mandatory coaching CI also runs real Node HMAC verification for cross-account, cross-session, locale, track, transcript and signature tampering. The transport/CAS caller still must be integrated and authenticated before this feature is enabled; no new endpoint or database is added here.

## Existing encrypted draft transport (typed continuation, activation OFF)
The existing authenticated draft endpoint now accepts a strict typed profile operation only behind HH_MY_COACH_PROFILE_V3_ENABLED. The same owner row, advisory lock, encrypted payload, CAS revision and erase/finalize path store the server ledger; ordinary checkpoint cannot overwrite an active profile. Acknowledged opening dialogue is retained as non-authoritative prefix, and only server-issued question/answer source IDs receive signed scores. Full ledger never leaves the server. A typed response bound to the issued prompt/attempt acknowledges that text prompt; it does not certify audio delivery. Existing profile ratings are never overwritten by a new track. This is not yet UI/voice integration or production activation. Native focused tests and signed-in DB/browser/device acceptance still required.
