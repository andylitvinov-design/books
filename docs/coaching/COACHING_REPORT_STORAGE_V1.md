# Coaching report storage — reconciliation draft

Production already has `app_private.coaching_session_records`, `coaching_session_consents`, `coaching_reports` and `coaching_report_versions`. Their seven migration statements were recovered read-only from the production migration ledger and their local MD5 checksums matched the ledger on 2026-11-09. Reuse those exact tables, owner RLS and `report_storage` consent triggers; do not create another report or session store. The legacy encrypted session row remains the authoritative source of answers.

On explicit report-save consent, the draft service locks and rebuilds the owner's completed session, verifies catalog identity, writes necessary session metadata, appends a `report_storage` consent event and inserts the confirmed encrypted report and immutable first version atomically. No raw answers or report text are stored outside ciphertext. Account and record IDs bind encryption AAD; a keyed content hash binds the current report, version and encrypted evidence. Accepted actions are not imported into My Coaching Plan.

The only new table contains bounded idempotency receipts, not client content. It is needed to reject changed-operation reuse and prevent a retry from resurrecting a deleted report; deleting a report tombstones its receipts. Limits are 128 active reports and 256 receipts per account, with no silent eviction. Account deletion cascades the session metadata, reports, versions, consents and receipts. Deleting the original coaching notes does not delete saved reports; the archive exposes separate confirmed deletion. The account export fails closed if an existing report format cannot be exported rather than silently omitting it.

The shared production consent trigger currently references a message-only field on report/event rows. The proposed migration corrects dispatch by table while preserving the required current consent and transcript-event binding. The fix was reproduced and tested only in an isolated database; it has not been applied to production.

**Known gaps:** older sessions lacking recorded scheme identity/timing are preview-only until a truthful, reviewed legacy provenance mapping is designed. The current service reads only its deterministic Report v2 format; mixed-format export fails closed. Review/edit history, plan import, canonical PDF, retention and consent-revocation UX, signed-in browser E2E and iPhone Safari remain open. The migration and all recovered source files require review before release. Rollback after real writes requires a reviewed backup/export and forward migration; dropping tables is not an automatic rollback.
