# Clarity P0 — cumulative logical session clock (26 November 2026)
Owner decision supersedes the previous one-token/one-day model in #5701.
- Clarity: three free logical sessions, 20 active minutes each; seven Discover practices are optional, not a replacement. A greeting or transport connection does not start the clock. A confirmed start/continue turn is required each time. One logical protocol ID per course day; multiple attributed coach/connection segments may contribute. Disconnect, pause and coach change freeze the same day; no homework and no new entitlement.
- Source candidate: `clarity-course-clock.mjs` implements the three-day sequential cumulative clock with exact millisecond caps, revision guard, fresh consent evidence, unique segments, coach identity and time attribution, no unobserved-gap credit. `clarity-course-clock-store.js` reuses the proposed encrypted account/day grant table, day 1 anchor, owner-scoped row lock + CAS. Neither an elapsed value nor a client flag is authoritative. The server result projection requires a matching trusted timed ending plus the existing first-day safe-field allowlist, confirmed opening, explicit separate homework acceptance and reviewed save. No proof means no homework. Local preview remains advisory. The updated parent homework answer and deterministic journal ID logic are preserved. The proposed SQL adds encrypted metadata to the already proposed table; it is NOT a deployed migration.
- **Release veto:** the existing direct browser-to-Google transport cannot yet prove continuous connected time or safely reissue an expired/closed transport credential for the same logical session. The legacy one-shot mint path is intentionally hard-disabled in this candidate. Neither flag is enabled. Do not release the old one-window entitlement or enable the new clock merely by changing env flags.
- Remaining integration: verified provider/Director adapter with server-clock observed connection and exact consent-turn evidence, durable adapter idempotency/ACK, bounded transport reservation and provider quota accounting, safe remint/close with no double issuance, cross-coach resume of the SAME encrypted protocol and per-entry attribution, UI clock from server status, Save/Edit/Cancel and compact four-block Daybook, #5703 field verification and #5673 consolidation. Provider transport usage and logical consented time are different ledgers; token expiration must not generate homework. No browser POST accepts trusted events. Do not add a paid Vercel audio proxy or a new paid provider. Prove feasibility with the existing free transport and official provider guarantees, or hold the release.
- Acceptance: consent/no-consent, greeting/reconnect before consent, partial 5+15 minutes with coach change, provider gap, stale/parallel revision, two owners under RLS, failed token mint, no overrun, 3×20 minutes only, no homework on stop/loss, exact saved protocol ID on timed ending, genuine authenticated iPhone Safari test and served production SHA. Verify migration via existing protected workflow only; no manual deploy or production writes in this candidate.
