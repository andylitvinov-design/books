# Goal logical run contract (draft, 27 Nov 2026)
Eight stable Goal topics, eight distinct immutable protocol IDs, one run ID and one personal goal ID. The shared Clarity ledger is parameterized internally by version and session count; existing Clarity state format and API remain unchanged. Goal has a separate clock version, 8 × 1200 seconds, gap <=15 seconds, revision CAS, fresh explicit consent for every segment, same logical protocol on reconnect or coach change. No elapsed credit after an unobserved gap or a stop. Time exhaustion is not proof of personal goal achievement. The paid access model is a proposed integration seam only: no price or sale is enabled.
 
## Activation gates
Reuse the reviewed shared account-scoped credential/entitlement and storage contract under #5701/#5756; do not create a parallel database or bypass account lock. Verify settled order and ownership server-side before constructing a run; bind the eight protocol IDs transactionally. Invalidate access for refund/dispute under existing checkout policy. Never accept browser clock events, a model reply or token mint as consent or connected-time evidence. Persist reviewed Results independently of the transcript and bind exact source revision, account, run, logical day; implement privacy export/delete and authenticated mobile acceptance. The current result-binding function requires the full trusted 1200 seconds; an early voluntary close needs its own explicit reviewed transition, not fabricated minutes. No new live endpoint, migration, feature flag or provider activation is included.
