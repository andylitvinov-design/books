# Wave Coaching Mode 2.1 — единый контракт сессии поверх PR #4850

**Дата:** 20 ноября 2026. **Тип:** углубление существующего Wave Coaching Director v4, НЕ новая субличность/модель/таблица/чат-бот.
**В клиентском интерфейсе ассистента зовут Ali; Wave — внутреннее техническое имя.**
**Целевая длительность:** 20 минут (1200 секунд), ориентир, не обязательство и не автомат завершения.

## 1. Три слоя одной беседы

- **Coach Persona:** характер, темп, теплота, прямота и характерные реплики. Источник: `persona-registry.mjs` + `coach-persona-speech-variants.mjs`.
- **Coaching Method:** одна основная методика на персонажа **для текущего этапа продукта**: `persona.methods[0]`, фиксируется существующим Director. Этапы, недостающие клиентские свидетельства и порядок определяет только `method-protocol-v4.mjs`.
- **Dialogue Director:** классифицирует последний ход клиента, знает, что уже спрашивал, какой факт клиент сообщил и чего не хватает для **текущего** этапа; из `coach-method-question-variants.mjs` выбирает 0–1 вопрос (две кандидатуры могут быть показаны одной и той же языковой модели); `coach-stage-response-variants.mjs` даёт 0–1 нейтральную реплику **по этапу**, `coach-persona-speech-variants.mjs` — характерный тон. Не пропускает этапы по таймеру или высказыванию ИИ.

Текущая привязка основной модели: **Мира → GROW, Макс → TGROW, София → Solution-focused, Алекс → TGROW, Мерлин → Appreciative Inquiry, Гарри → OSKAR, Лея → Appreciative Inquiry, Ной → WOOP, Ирис → OSKAR, Рэй → Appreciative Inquiry**. Названия вторых моделей в профиле — возможные варианты будущего выбора, но не право языковой модели менять технику внутри сессии.

## 2. Подробная временная карта (первичный 20-минутный формат)

В скобках — рекомендуемая продолжительность **этапа**, не установленное время переключения. Review — наша итоговая рефлексия/проверка с клиентом, даже если исходная методика не считает её частью оригинальной аббревиатуры.

| Метод | Последовательность этапов, минуты (в порядке протокола) |
|---|---|
| GROW | Goal **3** → Reality **6** → Options **5** → Way forward **4** → Review **2** |
| TGROW | Topic **2** → Goal **3** → Reality **5** → Options **4:30** → Way forward **3:30** → Review **2** |
| WOOP | Wish **3** → Outcome **3:30** → Internal obstacle **6** → If–then **5:30** → Review **2** |
| OSKAR | Outcome **4** → Scaling **3** → Know-how **5** → Affirm/action **6** → Review **2** |
| Solution-focused | Preferred future **4** → Exceptions **5** → Strengths **4** → Experiment **5** → Review **2** |
| Appreciative Inquiry | Discover **5** → Dream **4** → Design **5** → Deliver **4** → Review **2** |

В каждом методе суммарно ровно 1200 секунд. Продолжительность хранится прямо в исходных `step(..., recommendedSeconds)` текущего протокола и доступна только для справки через `coachMethodStagePlan`: `recommendedSeconds`, `nominalStartSeconds`, `nominalEndSeconds`, `requiredEvidence`. **Ни один таймер не даёт права поставить «этап завершён».** Достаточность ответа подтверждается клиентскими сведениями и правилами текущей методики; прояснённый ранее ответ не следует спрашивать заново, а отзыв/коррекция клиента может вернуть этап назад.

## 3. Полный контракт одного этапа

```text
{ method_id, step_id, phase, intervention_id,
  required_client_evidence[], missing_evidence[],
  recommended_seconds, nominal_position_seconds,
  question_candidates[3 per language],
  stage_response_variants[3 per language],
  persona_speech_acts[8 per persona and language],
  last_client_act, assistant_question_history,
  chosen_question_id|null, chosen_stage_response_id|null,
  choice_reason, server_authoritative_progress }
```

Порядок **одного ответа**:

1. Проверка безопасности, отказа, паузы, непринятия советов и явного запроса клиента — выше любой методики.
2. Внимательное чтение *последнего* ответа: что клиент действительно сказал, исправил, выбрал, что только предположил.
3. Определение одного текущего метода (для этого релиза — основного) и этапа **по свидетельствам клиента**, а не числу сообщений/секундам.
4. Отбор от 0 до 3 разрешённых вопросов этого этапа; удаление уже заданных/уже покрытых и предполагающих чужие чувства или решение. Проверка отсутствующих сведений.
5. Выбор **не более одного** смыслово подходящего вопроса; допускается ответ **без вопроса**. На неудобном/коротком голосовом фрагменте сначала только краткое уточнение.
6. Выбор этапной реплики: отражение/ориентация/интеграция, без приписывания клиенту фактов; предпочтение ещё не произнесённой фразе. Отдельно — узнаваемая манера выбранной субличности.
7. Композиция живого ответа (обычно 1–3 коротких предложения); модель может изменить формулировку, но не метод/этап/согласие и не может выпустить два вопроса.
8. После ответа — проверка подтверждённых клиентом фактов, обновление прогресса и условий следующего этапа; итоги и действие только с явным подтверждением клиента.

Пример внутри **GROW / Reality**:
- Возможные вопросы: «Что именно произошло в последнем таком случае?», «Какое ограничение уже подтверждено, а какое пока предположение?», «Что вы заметили сами, прежде чем делать выводы?».
- Реплики: «Здесь можно отделить события от возможных объяснений», «Конкретная ситуация полезнее слишком общего названия проблемы», «Уточним, какие ограничения подтверждены, а какие пока неизвестны».
- Манера Миры: мягкое приглашение без нажима. Манера Алекса: чёткое отделение фактов от гипотез. Но вопрос **не переходит к Options**, пока Reality не подтверждена.

Пример внутри **WOOP / Internal obstacle**:
- Внимание на собственную привычную реакцию, а не внешнюю помеху и тем более не «диагноз».
- Реплики: «Внутреннее препятствие — не диагноз и не неизменная черта», «Можно рассмотреть знакомый момент без обязательных подробностей».
- План «если — то» НЕ предлагается как готовый до того, как клиент сам прояснит препятствие и выберет ответ.

## 4. Что остаётся неизменным

Нет нового LLM, отдельного агента, облачного провайдера, CRM, платного сервиса, таблицы, cron, новой системы состояния или дублирующей логики переходов. Никаких текстов клиента в аналитических логах, автоматического обучения или вымышленных симптомов. EN/RU/ES, защита от повторов и отказов, закрытие по желанию, эмпатия и существующие голосовые каналы сохраняются. Профили и этапы можно расширять только после редакционного и тестового утверждения.

## 5. Приёмочные проверки

- Совпадение 31 реального этапа в 6 методиках, суммы секунд каждого метода = 1200; время не меняет `methodStepId`.
- Для каждого этапа и RU/EN/ES: три допустимых вопроса + три оригинальные этапные реплики; для каждого из 10 персонажей — 8 речевых актов в трёх языках.
- Предыдущая фраза коуча не должна дословно повторяться, если в банке есть новый вариант; завершённый клиентом пункт повторно не спрашивается.
- «Привет», «Не хочу отвечать», «Не давай советы», «Ты меня не понял», «Можно паузу?» и прямой вопрос клиента не должны порождать методическую анкету.
- Никогда не предлагать обязательный срок/план или диагностические интерпретации. Выбор следующего вопроса объясним кодом причины, без хранения приватного текста.
- Provider-free ответ использует этапную реплику и манеру персонажа, а существующий free/ZDR генеративный путь получает тот же контракт.
- Честные границы: защищённый PR/CI и GitHub merge НЕ равны проверенному Live, Vercel публикуется только штатным ограниченным выпуском.
