## Product contract / ТЗ

- P0: 300 seconds per registered Google account per calendar month; cumulative across sessions and devices. No minimum duration, no fixed number of calls. Proposed timezone America/Toronto, no rollover. The provider billing cycle is independent; use verified provider cycle, not calendar approximation.
- P0: verify existing Supabase session and Google identity on server; active customer profile, same-origin POST/CSRF, no user ID, quota, role, price or receipts from client input. Guest/non-Google cannot mint video token. Existing Google login/return path remains canonical. Do not weaken admin endpoint.
- P0: one global video channel shared by Lucas, coaches, owner tests and any other starts on this provider account. Reserve atomically before any provider call; refuse parallel calls (BUSY), even across devices. 2400 seconds customer budget plus 600 seconds reserve, absolute 3000 seconds and independently verified provider free remainder. Ten full 5-minute packages cannot be guaranteed with reserve. Deduct all provider usage including overhead and owner/coach calls; voice/text fallback separate. No paid fallback.
- P0: issue role-pinned, bounded, short-lived, non-replayable provider token only after reservation; vendor hard-stop duration plus connection delay must fit reservation and current periods. Use verified vendor start/stop/usage evidence (not browser clock). End on hangup, hidden tab, network loss or quota; uncertain provider stop holds the lease and reservation, pending trusted reconciliation. Idempotent settlement, actual provider cost separate from client video seconds. Provider overrun halts starts and requires audited operator reconciliation.
- P1: customer UI shows remaining mm:ss and reset date; busy notice RU/EN/ES and explicit Talk by voice / Try video later; show Video is available again only from fresh availability status, never auto-connect. 30-second warning; graceful same-chat voice fallback if available, otherwise text. Do not lose conversation context. Use existing compact header and Google login flow, do not create fake media. No automatic provider call on page mount.
- P1: admin controls and read-only counters for verified provider quota, customer/owner/coach usage, current lease (no client dialogue), uncertain stop and overrun. No cron/new paid infrastructure; use existing request/operational path and verified provider events. Keep all launch flags OFF until privacy/licence, free hard stop, reconciliation and actual video/audio acceptance are proven.

## Follow-up: official provider status adapter
Added `lukas-simli-readiness.mjs` and nine tests. The provider channel read is GET /ratelimiter/sessions (`currentUsage`); history is GET /history/sessions with sessionAggregator, startTime, endTime, sessionTotalTime, endReason. For future token minting, POST /compose/token accepts sessionAggregator and maxSessionLength. Use an opaque unique reservation UUID as aggregator, never an email/customer identifier. A matching history record is returned as **unverified**, with raw time fields, until vendor units, finalization, single-use token/replay behavior, and billing cycle/credit semantics are validated. Zero active sessions alone does not authorize releasing a pending reservation. Both GETs are read-only with timeouts, no retries, no redirects, no provider mint. Source: https://docs.simli.com/api-reference/active-session-count ; https://docs.simli.com/api-reference/retrieve-session-history ; https://docs.simli.com/api-reference/endpoint/webrtc/startAudioToVideoSession . Free plan described as personal use and testing; public customer release still requires confirming entitlement and privacy safeguards (https://www.simli.com/pricing ; https://www.simli.com/legal/terms-of-service).
