## 1. Механика эффективного онлайн-обучения в одном уроке

**Вся архитектура:** `ЦЕЛЬ → ВХОДНОЕ НАБЛЮДЕНИЕ → ПРАВО ВЫБОРА → ЗНАЧЕНИЕ → АФОРИЗМ → ПОКАЗ → ПОДГОТОВКА → ЗАМЕЧАЮ → ДЕЛАЮ → ПОВТОРЯЮ → НОВЫЙ КЕЙС → ПЛАН → ОБРАТНАЯ СВЯЗЬ → СОХРАНЕНИЕ → РЕЗУЛЬТАТ`.

Применяем **одну обучаемую микрооперацию в каждом уроке**, затем аккуратно повышаем независимость учебной попытки. Технологии и механизмы:

1. **Backward design / constructive alignment**: у каждого S1–S7 есть наблюдаемая цель («нашёл один видимый предмет», «отделил факт от предположения», «составил одну фразу») и учебная проверка на другом безопасном случае. Не подменять цель «посмотрел видео».
2. **Cognitive load / multimedia segmentation**: одно решение на один экран, короткие контекстные фразы и оригинальная спокойная иллюстрация; не показывать целый паспорт/пять подзадач на телефоне одновременно. Внутри практики подсказка открывается по запросу. Никаких одновременных обязательных озвучки, анимации, длинного текста и таймера.
3. **Worked example → guided practice → faded scaffolding → transfer**: №6 демонстрирует *конкретный акт*, №8 распознаёт элемент, №9 предлагает действительно выполнить, №10 — мягко воспроизвести с выбором подсказки, №11 — новый низкорисковый сюжет без повторения того же ответа.
4. **Retrieval practice и spacing**: дни 8–14 возвращаются к тем же S1…S7, но меняют бытовую ситуацию; на второй неделе можно сначала попробовать вспомнить правило, потом открыть подсказку. Подсказки всегда доступны, за них не штрафовать.
5. **Formative assessment**: после реального учебного действия обратная связь содержит *конкретную информацию о следующем возможном шаге*, а не только «молодец». Выбор в учебной сцене, реальная попытка, субъективный комфорт и намерение применить позже — независимые сигналы.
6. **Universal Design for Learning (UDL)**: три добровольных режима участия — маленькое упражнение, облегчённое упражнение, ознакомление чтением; одинаковая возможность использовать личный/вымышленный пример, нейтральный визуальный ориентир или без образов; разнообразие навыков, но не принуждение к травматическим воспоминаниям.
7. **Implementation intentions**: экран 12 строит `Если [неопасный сигнал] → могу [доступное действие] → иначе [резерв/отдых]`, а не обещание обязательного поведения.
8. **Trauma-informed instructional design**: автономия, прозрачность, возможности изменения способа, немедленная остановка и отсутствие медицинских обещаний. Эмоциональные ответы и мнение об афоризме **не бывают неправильными**.

**Что не применяется**: публичный leaderboard стресса; штраф за подсказку; количество кликов = владение навыком; лечебная экспозиция; принудительное глубокое дыхание; медицинские или гомеопатические назначения; autoplay со звуком; игровое давление/стыд за «низкий балл».

## 2. Карта 15 экранов и тип деятельности

| Экран | Онлайн-педагогическая функция | Визуально на телефоне | Как реагирует система |
|---:|---|---|---|
| 1 | Обозначить одно наблюдаемое учебное действие | Название + «сегодня научимся» + большая кнопка | Показывает следующую задачу, без отдельного опроса |
| 2 | Входное моментное наблюдение (не психометрический тест) | Один добровольный 0–10 рейтинг; обычная кнопка «Далее» работает и без числа | Если число выбрано — нейтральное подтверждение; иначе null |
| 3 | Управление уровнем поддержки | «Обычно / Проще / Только читать» | Выбранный режим меняет только подсказки/объём практики, а не оценку |
| 4 | Личная релевантность | «Мой фокус / Общий навык / Пока не уверен» | При отсутствии подтверждённых шкал — общий фокус, без новых тестов |
| 5 | Смысловая установка-афоризм, добровольное мнение | «Откликается / Сомневаюсь / Не согласен» (**БЕЗ Пропустить**) | Для сомнения/несогласия — нейтральная переформулировка, без повторного голосования |
| 6 | Worked example, предметная демонстрация | Одна спокойная картинка + «Посмотрите: сперва… потом…» | «Понятно / Нужен пример / Пока сложно»; подсказка именно по действию |
| 7 | Подготовить комфортный учебный формат | «Попробую / Облегчённо / Только посмотрю» | Ничего не запускается без выбора; доступен отдельный выход |
| 8 | Распознать/заметить | Одно конкретное микродействие + короткий вопрос | «Получилось / Частично / Пока нет / Не пробовал» → уточнить следующий шаг |
| 9 | Выполнить ключевое упражнение | Одна инструкция + поэтапная репетиция внутри карточки | То же + необязательная субъективная доступность 0–3, не `skillScore` |
| 10 | Вспомнить/повторить с меньшей подсказкой | «Самостоятельно / С подсказкой / Частично / Пока нет / Не пробовал» | Сохраняется **заявленная** попытка отдельно от hintUsed |
| 11 | Применить на **новом** безопасном случае | 2–3 осмысленных варианта ответа + «Показать пример» | Корректирующая обратная связь по действию; не «неправильная личность» |
| 12 | Составить условный переносимый план | Конструктор 1 сигнал + 1 доступная опора + резерв | «Составил / Только мысленно / Не планирую сегодня» — план не действие |
| 13 | Рефлексия процесса и добровольное `afterNow` | «Подошло / Частично / Без изменений / Не подошло», optional 0–10 | На неудобство → проще/отдых/выход, без принуждения к улучшению |
| 14 | Обзор **только реальных** ответов | Мини-карта + «Исправить / Сохранить» | XP/завершение только после идемпотентного server-confirmed save |
| 15 | Закрепить участие и перейти к карте курса | «День N сохранён» + один навык + одна опора | Отдельный экран после server-confirmed save, не требовать его в pre-save visit-order |

**Суммарный учебный ориентир:** ~10 минут 50 секунд/день, около 5 минут 50 секунд на экраны 8–11, цель **8–12 мин** на небольшом телефоне. Подсказки и таймер не обязательны. Не нужно 15 отдельных цифровых анкет; автоматическая обратная связь после выбранного действия может быть одной строкой.

## 3. Строгое отличие ОТВЕТА от управления уроком

**Ответы (предметные, добровольные):**
- `aphorismResponse`: **только `agree|unsure|disagree|null`**, не `skip`;
- `practiceAttempt`: `tried|partly|not_yet|not_attempted|uncomfortable|null` (последний — **сообщение о состоянии удобства**, запускает безопасный стоп; не диагноз);
- `hintUsed`: `true|false` только если действительно человек открывал подсказку;
- `focusChoice`: собственный проверенный фокус/общий/не уверен;
- `lessonMoment`: optional number 0–10; отсутствие = null, не ноль;
- `easeOfAttempt`: optional 0–3, только субъективная доступность одного действия; не % освоения;
- `transferStage`: `planned|imagined|not_planning|reported_used|null` с чётким отличием намерения от выполнения;
- `scenarioChoice`: ID конкретного вымышленного варианта, **не** балл здоровья.

**Навигация вне ответов:** «Назад», «Далее», «Пауза», **«Закончить»** — системные элементы, не варианты ответа. **«Далее»** (разрешено без добровольного ответа), «Подсказка», «Пауза», «Закончить урок» — отдельные универсальные controls. **Кнопки «Пропустить», «Skip», «Пропускаю», «Я пропускаю ответ» не выводить** как ответ ни на одном из 210 экранов. Если человек ничего не выбрал и нажал «Далее», записать null; это не означает несогласие, «частично» или попытку. На screen 5 остаются три самостоятельных ответа, все не требуются для продолжения; при нет выбора neutral state.

**Стресс-чувствительные задания:** «Некомфортно» — не опция «Пропустить», а явный информативный сигнал stop. При нём отключить озвучку и таймер, показать отдых или нейтральную внешнюю ориентировку и возможность завершить. Не запускать следующие упражнения автоматически.

## 4. Система формирующей обратной связи (не баллы личности)

Каждый содержательный ответ **триггерит один конкретный следующий полезный шаг**:

| Ответ | Короткая реакция | Вариант продолжения |
|---|---|---|
| Удалось | «Вы попробовали этот шаг. Если он удобен, оставим его». | «Далее» |
| Частично | «Уже можно работать с этой частью. Давайте сделаем следующий шаг меньше». | «Проще» / «Подсказка» / «Далее» |
| Пока нет | «Бывает. Покажем конкретный пример без увеличения нагрузки». | «Пример» / «Другая опора» / «Далее» |
| Не пробовал | «Пока это было только знакомство; отметим его отдельно». | «Прочитать» / «Вернуться позже» |
| Некомфортно | «Останавливаться — подходящий выбор». | Немедленное прекращение аудио/таймера, отдых или закрытие |
| Правдоподобный выбор на учебном кейсе | «В этом примере вы заметили ___ и подобрали ___». | Новый сюжет, без начисления клинических баллов |
| Мягко небезопасный выбор на учебном кейсе | «Проверьте: здесь есть вариант без усилия/самокритики. Посмотрим ещё один пример?» | Конкретная демонстрация, возможность выбрать по-другому |
| Сомневаюсь в афоризме | «Сомневаться нормально. Можно проверить лишь доступность действия». | Перейти к показу |
| Не согласен в афоризме | «Спасибо. Можно взять более нейтральную фразу: …». | Перейти к показу без переубеждения |

**Нельзя**: «Неправильно», «Вы не справились», «Вам осталось вылечить стресс на 70%», «Попробуйте глубже», «Вы обязаны принять афоризм». Не все ответы должны быть в виде оценки 0–3: на экране 6 достаточно «Понятно / Нужен пример / Пока сложно», на 11 — корректирующей обратной связи по ситуации.

## 5. Матрица S1–S7: конкретные учебные цели

| ID | На первой неделе человек пробует | На второй неделе он пробует воспроизвести в новом сюжете | Что фиксируем |
|---|---|---|---|
| S1 | Различает событие, ранний сигнал и малый посильный ответ | Сигнал в другом бытовом контексте без обязательной подсказки | Выбранный сигнал + реальный самоотчёт |
| S2 | Находит реальный внешний ориентир и добровольно переключает взгляд | Выбирает ориентир без готового списка | Категория внешней детали + сообщение о попытке |
| S3 | Выбирает движение, нейтральную ориентировку или отдых | Подбирает под контекст «много требований / мало сил» | Тип поддержки, доступность и предпочтение |
| S4 | Называет мягкое возможное чувство персонажа + заботу | Снова выбирает эмоцию и нейтральную опору в другом сюжете | Учебное слово + забота, не реальное травма-воспоминание |
| S5 | Отделяет проверяемый факт от догадки | Добавляет одну ценность и небольшой посильный шаг | Учебная классификация + осознанный выбор |
| S6 | Создаёт уважительную фразу границы | Репетирует ответ на вторую просьбу в вымышленном диалоге | Тип фразы + уровень помощи, не факт реального разговора |
| S7 | Собирает «сигнал → опора → резерв» | На новом примере выбирает один реальный подходящий способ | Личная карта из фактических выборов, не 7/7 освоено |

## 6. Технический и редакционный QA до выпуска

- На телефоне **один главный смысл/одно взаимодействие на экран**, фиксированный нижний CTA, safe-area, 320/360/390/430px, 200% text zoom, клавиатура и скринридер; не допускать горизонтальной прокрутки. При увеличенном тексте допускать вертикальную, не обрезать.
- Все кнопки имеют понятные названия, не отличаются только цветом, кнопка «Мне некомфортно» всегда доступна и останавливает всё; при закрытии сохранять только явно согласованные ответы, а не вымышленную историю прохождения.
- На каждый день требуются **три отдельные исходные сцены**: показ №6, первая практика №8/9 и **новая** независимая сцена №11. Не просто повторить персонажа с другими именами. Неделя 2 использует другие задания для S1–S7.
- Связка №8–11 имеет четыре разные дидактические операции (распознать → выполнить → воспроизвести → перенести). Если это четыре вопроса о том же самом, урок не проходит QA.
- Структура и тексты RU/EN должны быть редакционно вычитаны; афоризмы существуют RU/EN, полноценные 210 EN microcopy ещё **не** подготовлены. Нельзя подставлять RU в EN.
- Проверять продуктовые поля API перед реализацией: `skip` у старых V3/V5 курсов — исторический legacy enum и должен сохраняться в их сохранённых записях. Для **новой** версии не показывать этот вариант и не генерировать новые `skip`-ответы. Не изменять историю пользователей, все изменения version-pinned.
- Программный QA: 14 × 15 экранов, **ноль опций ответа «Пропустить»**, 14 × 3 афоризма, содержательная корректирующая реакция на `partly|not_yet|uncomfortable`, возможность back/exit без forced answer, сравнительные self-report пары без фиктивного нуля, успешный сохраняющий API (idempotent), экран 15 только после confirmation, сохранение старого runtime.
- **Критерий публикации:** отдельный PR с новым contentVersion и slideModel, EN/RU-локализацией, адаптивным интерфейсом, серверной валидацией, регрессией, production READY и реальной проверкой на смартфоне. **Этот документ не означает выпуск на live.**
