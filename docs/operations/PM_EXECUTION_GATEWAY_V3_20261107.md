# Holistic House · Project Management Execution Gateway 3.0

## Architecture
Owner-only `/admin/project-management` extends the existing Epic → Plan → Task → PR graph and the private `cc_pm_events` idempotency ledger. The public PR Monitor remains read-only.

**Dispatch path:** authenticated owner → `prepare_execution` (current PR and exact-head failed Core proof) → explicit owner confirmation → UUID reservation in existing private database → GitHub official `workflow_dispatch` to **existing** Watchdog on `codex/bootstrap-books` → trusted single-writer Dispatcher → existing signed `RESERVED` comment with `task_key`, `head_sha`, `owner_run_id` → existing Repair Worker → guarded publisher → required Core, Specialist and `hh-merge-check` → protected merge → independent Vercel and functional LIVE proof.

A workflow dispatch HTTP 204 is **DISPATCH_ACCEPTED**, not a runner, patch or commit. Owner request UUID is included in the Watchdog run name for a bounded run-history readback. Actual started `direct-handoff` job is a separate RUNNER_STARTED observation. The Worker creates its own signed reservation; the web API never signs or manufactures it.

## Fail-closed gates
- No automatic source execution unless `VERCEL_ENV=production`, `HH_PM_EXECUTION_ENABLED=true` and an existing owner-approved repository-scoped `HH_PM_GITHUB_ACTIONS_WRITE_TOKEN` is present in Vercel **Production** only. Do not paste credentials in chats, logs, commits or PR descriptions. No token is generated by this PR.
- Token needs GitHub fine-grained repository **Actions: Read and write** and **Metadata: Read** for `andylitvinov-design/books`. The actual 204 or 403/404/422 GitHub response is the authoritative dispatch permission proof; mere token presence is not.
- Same-origin owner session, rate limits, UUID request IDs, DB advisory lock, same-fingerprint and same-HEAD duplicate prevention. An ambiguous HTTP/network response is never automatically retried.
- Only approved `code_change` task with linked PR; no Draft, foreign branch, stale SHA, manual hold, specialist-only failure or non-Core red. Trusted Watchdog proof and existing source allowlist still independently gate execution.
- Retry only with new independently confirmed source HEAD/failure, up to 3 attempts; unknown delivery is a blocker. Cancel records a stop for future attempts only, never cancels mandatory CI.
- No new workflow, cron, worker, paid inference, provider or credentials. Existing free OpenRouter adapter remains in the isolated Worker and retains its zero-price/no-fallback policy.

## Modes
- **Auto Free Repair**: real GitHub dispatch only when enabled and admitted. The server does not call free AI directly or hand GitHub credentials to any model.
- **ChatGPT Work**: owner-initiated copyable full task handoff and ChatGPT link. No unsupported API, no false automatic execution.
- **Codex Host**: visible but disabled until documented OAuth, supported hosting/runtime and inference/permissions are independently verified. No subscription-as-API assumption.

## Deployment and acceptance
1. Merge the trusted control-branch PR only after its existing watchdog-contract and queue tests. Verify the workflow inputs on `codex/bootstrap-books` before enabling production owner launch.
2. Merge the product PR through current Core/Specialist/`hh-merge-check`; apply and verify additive private migration before using new actions.
3. Configure the already-approved Actions write credential and `HH_PM_EXECUTION_ENABLED=true` only with owner approval, verified budget, and control branch deployed. Leave OFF if any prerequisite is unknown.
4. In owner PM, select a genuinely RED, safe, non-manual source PR. Prepare, approve and dispatch. Record the exact Watchdog run ID and started direct-handoff job, signed reservation, Worker run ID, verified candidate patch, guarded commit old/new SHA and PR HEAD readback.
5. Observe fresh exact-HEAD Core, Specialist, hh-merge-check, protected merge, production Vercel READY SHA/ancestry and scoped functional smoke. Until then, task is **NOT LIVE_VERIFIED**.

## Operational caveats
A successful Watchdog/Worker run without a new commit is not a repair. A merged PR is not automatically LIVE. GitHub Actions usage may incur existing metered quota; no new paid service is authorized. All errors must surface as blockers, not fabricated successes.
