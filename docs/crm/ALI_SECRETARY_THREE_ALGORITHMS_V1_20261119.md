# Ali: три алгоритма секретаря — 19.11.2026

**Один Ali, три серверных алгоритма без новых моделей.** Выбор роли не производится из свободного текста клиента. Диспетчер `lib/assist/ali-secretary-algorithms.mjs` принимает только подтверждённую сервером услугу или отдельный подписанный вход.

| Алгоритм | Этапы | Результат |
| --- | --- | --- |
| Secretary (`secretary`) | Выбранная услуга → согласие → время/помощь → формат при необходимости → проверить → отправить | Короткая заявка. Никакой психотерапевтической беседы, выдуманного бронирования или платежа. |
| Secretary Psychologist (`secretary_psychologist`) | Отдельное добровольное согласие → ситуация → цель → препятствие → влияние → попытки → поддержка → резюме → отдельное Send | Мягкий необязательный предварительный разговор. Без диагностики, поиска скрытых причин, обещаний и автоматической передачи личных данных. |
| Secretary Diagnostician (`free_diagnostic`) | Секретарь подтверждает выбранный бесплатный разбор → согласие → **три вопроса**: цель, трудность, нынешняя ситуация → рисунок (необязательно) → резюме/Send → анкета с квитанцией → личное фото (необязательно) → готово | Материалы в существующей защищённой CRM, только после подтверждения клиентом и проверки каждого файла/формы. |

## Соответствие опубликованным услугам

- Обычные сеансы, консультации, Рейки, записи, курсы: Secretary; уже выбранную услугу второй раз не спрашивать.
- Команда `/start hhpsych_<ru|en|es>`: Secretary Psychologist **только** после отдельного согласия.
- `/start hhreview_<ru|en|es>` и `hhdiagnostic_`: Secretary Diagnostician, как прежде.
- Подписанные предложения `browse_situation`, `consultation_free`, `homeopathy_free`, `business_review` из каталога бесплатных письменных разборов теперь переходят из короткого подтверждения секретаря в диагностические три вопроса и существующий защищённый набор материалов. Цена, тип, URL и идентификатор предложения должны совпадать с опубликованным каталогом; неподтверждённый ID — обычный безопасный ответ, но не сбор фотографий.
- `personal_express_review` и `personal_extended_review` пока работают через отдельный Telegram Business: у них есть собственная анкета заявки, **но нет подтверждённой защищённой цепочки рисунок/анкета/личное фото V3**. Не считать эти услуги завершённой интеграцией; существующий PR #5187/#5170 их изменяет.
- Общий web-chat `/api/holistic-agent/turn` не содержит подписанного выбранного заказа и доказательства отдельного согласия на глубокую беседу. Не включать персональную психологическую диагностику по тексту сообщения. Ссылки выбора услуг на сайте приводят к подписанным Telegram entry, где этот протокол работает.

## Безопасность и приёмка

Собственное имя Ali, один короткий вопрос за ход, не повторять известное, уважать STOP/паузу. Три вопроса обязаны совпадать с тремя слотами `freeCoreAnswersReady` до показа рисунка. Устаревшие шестиэтапные интервью и дополнительные факты сохраняются. Лицо и рисунок не используются для диагноза/вывода о личности. Файлы JPEG/PNG до 5 МБ подтверждаются фактической Telegram receipt; анкета — реальным submit; фраза «я отправил» не считается квитанцией. Ничего не идёт специалисту, пока клиент не проверит резюме и явно не нажмёт Send. Дубли webhook не создают повторный лид.

Тесты: `node --test tests/ali-secretary-algorithms.test.mjs tests/ali-free-diagnostic.test.mjs tests/ali-free-package-receipts.test.mjs tests/wave-free-review-flexible-dialogue.test.mjs tests/crm-wave-secretary-modes.test.mjs tests/crm-telegram-service-options.test.mjs tests/ali-secretary-offer-journeys.test.mjs`.
