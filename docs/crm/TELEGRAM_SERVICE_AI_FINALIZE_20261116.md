# Telegram V3 service request finalization (E2/E3)

Master specification: #4764. Parent (E1): #4767. This is an additive, stacked implementation over the approved selected-service V3 interview, not a new bot or CRM.

On explicit client **Send request**, the signed Telegram webhook first commits the encrypted V3 transcript, service identity and client-approved summary in the existing CRM Messenger thread. It then calls the finalizer under its current owner-scoped signed identity, rechecks active V3 consent, client STOP, current owner account and unsuppressed Telegram thread, and inserts one practitioner-scoped `app.public_service_enquiries` request via the existing backend RLS transaction. The same V3 UUID is used for the enquiry record so the client, transcript and CRM service request share a single HH reference.

The finalizer attaches an encrypted one-off Telegram contact marker without manufacturing phone/email, links the actual CRM thread and saves a durable existing owner notification intent in the same backend transaction. It invokes the existing owner Telegram pilot and `@Andydotbot` delivery only after verified owner bot identity, per-topic consent and committed enquiry. The notification sends public service metadata and HH reference only; not the client's private answers, summary or peer ID. Provider API acceptance is not delivery proof. The existing recovery route can inspect unclaimed notice intents.

Both signed V3 STOP and backend creation use the **same advisory session lock**. If STOP commits first the submission cannot pass the V3 consent read; if the service enquiry commits first, later STOP prevents further messages without retracting the already submitted enquiry. Repeated Send or `/retry_request` resolves to the same operation UUID and cannot create another public enquiry or notification. A CRM failure is shown as unconfirmed to the client, not as a false success.

No new database migration, queue, workflow, model, bot, credential, paid API or release channel. **LIVE still requires** parent then child protected merges, exact-head Core+CRM/Auth/RLS/privacy tests, verified Vercel production alias/sha through existing scheduled hourly publisher, real second-account Telegram consent→interview→confirm→CRM→Andydotbot delivery→manual reply and STOP proof. Do not activate unverified Telegram Business Chat Automation or infer cabinet identity from a chat username.
