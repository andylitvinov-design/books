# Holistic House · новые сообщения внутри кабинета мастера

**19 октября 2026, Toronto.** Надстройка к [клиентским профилям и очереди ответов](./PRACTITIONER_CLIENT_PROFILES_REPLY_QUEUE_20261019.md). Не относится к Telegram/WhatsApp/Meta delivered/read receipts.

## Что меняется

- **«Ждут моего ответа»** по-прежнему означает, что по заявке последнее общее сообщение от клиента или новая заявка ещё не обработана.
- **«Новые сообщения»** — отдельный счётчик только тех сообщений, которые написал клиент внутри Holistic House и которые мастер **явно не отметил просмотренными**. Внутренние заметки мастера и ответы самого мастера не считаются новыми клиентскими сообщениями. Новое письмо в WhatsApp/Telegram не появляется здесь без официальной подключённой интеграции.
- В карточке клиента появился индикатор новых сообщений; внутри истории переписки кнопка **«Отметить просмотренными»**. Она доступна только при явном открытии чата и отмечает одно последнее сообщение другого участника, которое действительно пришло в загруженной истории. Случайное открытие карточки не изменяет счётчики.
- После подтверждения отметки кабинет мастера перечитывает свой список. Клиент может аналогично отметить просмотренным ответ мастера в собственном кабинете → Консультации, но отметка другого лица не раскрывается.
- Не используется таймер, автодоставка, email, Telegram, WebPush, серверный cron или сторонняя аналитика. Не создаются записи в клиническом кабинете клиента.

## Техническая безопасность

- Supabase migration `20261019174312_hh_practitioner_request_read_state_20261019.sql`: `app.practitioner_request_reads` с `request_id`, `account_id` и `last_seen_at`. **Нет содержимого переписки.**
- Таблица `FORCE ROW LEVEL SECURITY`, роль `hh_app_backend` может читать/писать только свои записи при активной учётной записи и доказанном участии в точной заявке; `anon`/`authenticated` не имеют прямых прав. Отдельный мастер не получает доступ к чужим клиентам.
- `markSeen` сначала проверяет сессию через `createRequestAuth`, `X-HH-Account-Id`, наличие разрешения на заявку, UUID именно загруженного чужого сообщения, `visibility='participants'` и совпадение `request_id`. После этого атомарный `INSERT…ON CONFLICT DO UPDATE` монотонно сдвигает `last_seen_at`, никогда не сбрасывая отметку назад.
- Счётчики собираются одним owner-scoped SQL-запросом по идентификаторам **только заявок мастера**. `EXPLAIN` проверен: используются `practitioner_request_messages_history_idx` и `practitioner_request_reads_pkey`.
- В UI EN/RU/ES индикаторы различают `awaiting reply` и `new to me`; нет ложных подтверждений прочтения в сторонних мессенджерах.

## Проверить перед объявлением полной готовности

1. `node --test tests/practitioner-client-crm.test.mjs` и весь `Holistic House CRM source checks`.
2. В двух разных тестовых аккаунтах: клиент отправляет ответ → у своего мастера появляется `Новые сообщения: 1` → мастер открывает диалог и нажимает `Отметить просмотренными` → счётчик становится нулём, а `Ждут моего ответа` остаётся до фактического ответа.
3. После ответа мастера `Ждут моего ответа` исчезает; новая реплика клиента снова вызывает индикатор. Внутренняя заметка мастера не влияет ни на `new`, ни на `awaiting`.
4. Пробовать чужой `requestId`, чужой `messageId`, master-only `note`, повторную и устаревшую отметки: все попытки отклоняются либо остаются монотонными.
5. Production Vercel READY по точному SHA, чтение настоящего Live, без новых runtime errors.

**Ограничение:** пока реальная переписка не проверена двумя авторизованными тестовыми учётными записями, подтверждена только модель доступа, SQL и программный контракт; это не доказательство клиентской доставки или уведомления.
