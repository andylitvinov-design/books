Это матрица возможностей CRM и этапов внедрения, а не обещание, что все внешние сервисы уже включены. Канонический сайт: https://holistichouse.vercel.app. Рабочая production-ветка: codex/public-book-library.

## Целевой рабочий процесс

Лид с сайта / курса / личного контакта → подтверждение личности и разрешённого канала → карточка делового контакта → тип запроса и этап сделки → задача и дата следующего действия → запись с подтверждением → услуга / курс → подтверждённый счёт и оплата → последующая связь по согласию. Мастер видит только назначенные ему заявки и их защищённые внутренние сообщения. **Нельзя** автоматически объединять публичный CRM-контакт с клиническим кабинетом по имени, телефону или email.

## Модуль v6 — центр ежедневной работы CRM

- Раздел **«Задачи»**: Срочно / Просрочено / На сегодня / Позже / Все; поиск по имени клиента и виду действия, EN/RU/ES, большие элементы управления на телефоне.
- Даты и агрегаты рассчитываются сервером по America/Toronto, а не по часовому поясу устройства. Полные счётчики не подменяются количеством в загруженных первых 300 задачах; если список неполный — явное предупреждение.
- Из задачи можно открыть именно её контакт даже за пределами первых 50 строк каталога. Точный ID ищется по серверному POST, который требует owner auth, Origin, совпадение идентификатора аккаунта и owner-scoped запись под ограниченной ролью hh_crm_backend с FORCE RLS.
- Действия изменения даты, выполнения и отмены используют прежний revision/idempotency-контракт. Открытие карточки не меняет статус задачи и не отправляет сообщения.
- Переход к контакту ставит клавиатурный фокус на нужную карточку. Не выгружать личные письма, ответы тестов, клинические документы и секретные ссылки в CRM.

**Gate:** полный набор функциональных проверок + regression тесты поиска/ownership + production build + Vercel READY по точному SHA + две авторизованные тестовые учётные записи для фактической приёмки. Работа с реальными аккаунтами и телефоном не считается выполненной по синтетическим тестам.

## Правила безопасности и стоимости

1. По умолчанию не отправлять автоматические маркетинговые сообщения, не запускать платный канал или шаблон без проверенного права/бюджета; расходы на платную отправку — 0 до отдельного согласования.
2. Для каждого действия с object ID повторять контроль прав на сервере и в базе; не доверять идентификатору или отображаемой роли в браузере. OWASP API Security: broken object authorization — ключевой риск.
3. Сохранять только деловые поля. Отдельные клинические документы, результаты тестов, препараты и личные сообщения остаются в защищённом Client Cabinet. Не помещать их в рекламные метаданные и внешние мессенджеры.
4. Историю провайдера считать доставленной только после соответствующего provider receipt. HTTP «accepted» не означает «delivered». Автоотправки не включать из-за одного успешного теста.
5. Перед любым выпуском: regression CI, полный Next.js build, точный Vercel deployment SHA, проверить доступ и откат. При миграции отдельно проверить FORCE RLS и состояние production schema.

## Инструкция владельцу для модуля v6

Перейти в **Моя практика → CRM → Задачи**. Просмотреть «Срочно», затем «На сегодня», нажать «Открыть контакт», изучить деловую карточку, после разговора создать следующее действие. При завершении/переносе использовать кнопки задачи и проверить новые агрегаты. Если количество открытых задач превышает число загруженных строк, не считать непоказанные задачи завершёнными. Внешних сообщений этот сценарий не отправляет.
