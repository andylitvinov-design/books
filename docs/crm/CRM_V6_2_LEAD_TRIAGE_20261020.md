# CRM v6.2 — лид без действия → план ответа

20 октября 2026, America/Toronto. Owner tracking: https://github.com/andylitvinov-design/books/issues/985. Production branch codex/public-book-library.

## Пользовательский сценарий

My Practice → CRM → Лиды показывает все деловые контакты в статусе lead, у которых нет открытой задачи. Не ограничивается первой страницей общего списка: независимый постраничный поиск 25 элементов, полный счётчик на обзоре. Видны только имя, дата, источник, язык и неавторизационный код HH- заявки. Нет личного описания ситуации, курса или результатов тестов.

Владелец нажимает «Запланировать ответ» → повторная проверка прав и состояния контакта → внутренняя CRM задача reply на сегодня в часовом поясе Торонто. Повторная попытка или две вкладки не создают дублей: транзакция блокирует контакт и повторно проверяет открытые задачи. «Открыть контакт» ведёт к приватной карточке; это не отправка сообщения, не подтверждённая бронь и не оплата.

## Защита и масштабирование

- Использованы существующие app.crm_contacts и app.crm_followups, без миграций/новых прав, внешних сервисов и платных вызовов.
- Новый POST /api/app/crm/leads: same-origin, authenticated owner, X-HH-Account-Id, practitioner allowlist, hh_crm_backend, account_active, FORCE RLS. Курсор HMAC привязан к владельцу и хранит только UUID и микросекундные created_at; в HTTP URL не помещаются контакты.
- SQL: lifecycle=lead; suppressed=false; NOT EXISTS любой открытой задачи того же owner/contact. Это лишь «без открытого follow-up», а НЕ «не отвечали» или «платёж ожидается».
- Запросы ограничены 25 строками, есть ручная подгрузка, перезапрос и удаление дублей. EN/RU/ES, кнопки от 44px, мобильные 320–430px.
- При запрещённом/архивном контакте операция завершается отказом. После успешного планирования задача появляется в существующей очереди CRM. Нет маркетингового opt-in, auto email/SMS/Telegram/WhatsApp/push и записей в clinical profile.

## Evidence и открытые блокеры

Профильные source и runtime тесты защищают signed cursor, owner-scope, шифрование/проекцию, идемпотентность, конфликт стадий, повторный запрос и UI. Выпуск — только после профильной CRM CI, отдельной Next.js production build, merge и проверки Vercel READY/alias/SHA.

Read-only production SQL EXPLAIN использует действующие индексы crm_contacts_owner_recent_idx и crm_followups_owner_status_due_idx; FORCE RLS активен, прямого SELECT anon/authenticated нет. На момент аудита база имела 0 CRM контактов, 0 follow-ups, 0 публичных заявок. Это не доказательство реального двухаккаунтного E2E.

Открыты: настоящая цепочка клиент → назначенный мастер → ответ → просмотр, отказ чужого мастера, физический push, подтверждённые provider receipts Telegram/WhatsApp/SMS/оплаты, расписание без двойной брони, помощник с узкими правами, retention. Не связывать клинический Client Cabinet и деловые CRM контакты по совпадению имени/телефона.

Инструкция владельцу: https://holistichouse.vercel.app/ru/app/practice → CRM → Лиды → «Запланировать ответ» → «Открыть контакт». Следующие действия в «Задачи».
