# Ali — безопасный индекс диалогов и контроль качества (2026-11-16)

## Границы охвата

- CRM app.crm_msg_items остаётся единственным шифрованным первоисточником для провайдерского Telegram/WhatsApp/Instagram/Messenger, если их собственный подписанный канал действительно настроен и сообщение было записано.
- Agent History уже требует отдельного согласия на хранение; журнал индексирует только сохранённые пары, не весь браузерный поток.
- Коучинг индексирует только сообщения, уже зафиксированные в разрешённом архиве coaching_session_messages, не аудио и не временную речь.
- Telegram Business сообщения из личного аккаунта и неподключённые WhatsApp каналы **не считаются охваченными**. Доставка провайдера и ручные ответы подтверждаются отдельно.

## Принцип безопасности

Таблица app_private.wave_conversation_receipts содержит только тип источника, внутренний UUID первоисточника, owner scope, канал, направление, подтверждённый текущий статус и момент; нет текста, ciphertext, контактных данных или внешних идентификаторов. Привязка route_version намеренно пуста, пока нет проверенного per-turn provenance. FORCE RLS, запрет прямого чтения для client/backend roles; только SECURITY DEFINER триггеры и агрегирующая функция для серверного admin view. Удаление сообщения удаляет квитанцию. STOP по-прежнему обрабатывается первоисточником; сохранение истории отдельно от согласия на анализ.

## Как выпускать

1. Релиз только через защищённый PR, точный Core/Specialist/privacy/RLS, без новых Vercel deploy и CI волн.
2. После merge миграция 20261117005500_wave_conversation_receipts_v1.sql должна быть применена ровно один раз. Сначала проверить наличие версии в Supabase migrations, затем SQL schema, FORCE RLS, права и отсутствие anon/auth grants.
3. Прочитать агрегат select * from app_private.wave_quality_receipt_summary(31), сверить с app.crm_msg_items по channel/direction/status (учесть исторические backfill), отдельно проверить свежую подписанную входящую и исходящую запись, статус провайдера, STOP и удаление в тестовом scoped аккаунте.
4. Проверить, что /admin/learning доступен только владельцу, нет экспорта текстов и виден PARTIAL_COVERAGE либо SCHEMA_NOT_DEPLOYED, а не ложный глобальный ноль.
5. Для обязательного полного покрытия Telegram Business и WhatsApp продолжить #4797 с отдельным проверенным identity + consent flow, без дешифрования истории в LLM. Никакого автоматического обучения на клиентских сообщениях.
6. Ежедневный раздел Ali QA уже встроен в существующую утреннюю автоматизацию, но может анализировать лишь разрешённые агрегаты, проверяемые синтетические кейсы и protected PR. Не интерпретировать полезность из отсутствующих оценок.
