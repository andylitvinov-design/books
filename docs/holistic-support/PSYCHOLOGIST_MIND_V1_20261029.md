# Holistic Intelligence — Psychologist Mind v1

**29 октября 2026 · source implementation / отдельный алгоритм.** Не клинический продукт, не лицензированный психотерапевт, не live-развёртывание.

## Назначение

Одна субличность «Психолог» выполняет две функции поверх общей методологии:
- формирует **структурированную персональную программу из восьми сессий** с целями, направлениями и допустимыми методами;
- формирует **один клиентский ответ** и следующий уточняющий вопрос, учитывающий тот же план и его текущую сессию.

Восемь сессий — формат программы Holistic House, **не универсальный срок лечения**. Алгоритм не ставит диагноз, не исследует травматическую память автономно, не делает произвольных выводов об истории человека.

**Реализация:** lib/holistic-support/psychologist-mind.mjs, типы lib/holistic-support/psychologist-mind.d.mts, тесты tests/psychologist-mind.test.mjs. Экспорт осуществляется через общий lib/holistic-support/holistic-intelligence.mjs.

## Шесть внутренних интеллектуальных функций

1. **Психолог-аналитик:** изучает текущий запрос, ресурсы, триггеры и реакции. Источник факта — клиент, а не догадка модели.
2. **Формулировщик 5P:** актуальная трудность, предрасполагающие обстоятельства, запускающие события, поддерживающие факторы, защитные ресурсы. Неизвестное остаётся unknown; гипотезы помечены как tentative.
3. **Методолог:** выбирает основную модель CBT, ACT или interpersonal и безопасные упражнения.
4. **Куратор символдрамы:** может предложить только необязательную ресурсную имагинацию при отдельном согласии. Полноценная KIP, интерпретация символов, работа с регрессией — только со специалистом.
5. **Архитектор программы:** восемь последовательных целей, ограничения, T0/T1, повторная проверка безопасности перед каждой практикой.
6. **Диалоговый проводник:** использует выбранный фокус и метод текущего занятия, задаёт ровно один вопрос, предлагает сделать паузу и корректирует темп.

Обязателен отдельный **Safety Guardian**: safety preflight предшествует всем остальным функциям.

## Направления и границы

| Подход | Автономное применение |
|---|---|
| CBT | Только психообразовательные навыки: карта реакции, наблюдение мыслей, небольшие эксперименты |
| ACT | Работа с ценностями, выбором, ресурсами |
| DBT-skills | Низкоинтенсивные навыки саморегуляции |
| Interpersonal | Рефлексия границ и навыки диалога |
| Психодинамика | Клиническая концептуализация/интерпретация только человеком |
| Символдрама/KIP | Клинический метод только со специалистом; отдельная простая ресурсная визуализация не называется полной KIP |
| EMDR, CPT, prolonged exposure | Только как научно обоснованные направления для квалифицированного специалиста, не автономные процедуры AI |

**Тематические маршруты:** стресс, отношения, самооценка/самокритика, жизненные ценности/смысл; травма — только human review или непубликуемый practitioner draft на поддерживающих методах, не «8-сессионное лечение ПТСР».

Каркас восьми занятий: понимание запроса → ресурсы → схема реакции → работа с допустимой темой → убеждения/границы/самоотношение → безопасная альтернатива → перенос в жизнь → интеграция. Методы и порядок могут различаться по маршрутам; каждый шаг остаётся необязательным.

## Приоритет принятия решения

1. Срочный риск (явный upstream triage, плюс существующий локальный parser из guide-dialogue.mjs) → human handoff, без сессий.
2. Клинические red flags, переработка травматической памяти, несовершеннолетний клиент → только профессиональная оценка.
3. Неизвестный/отсутствующий preflight → safety_check_required, никаких упражнений.
4. Текущий добровольный выбор клиента → выше старых профиля и памяти.
5. Подтверждённый профиль/память → только после проверки владельца и отдельных согласий.
6. Концептуализация по 5P → только обоснованные источники, неизвестные параметры не заполняются догадками.
7. Проверка запретов методов, согласия на ресурсные образы, комфорта, языка.
8. Генерация плана или одного диалогового вопроса. Сохранение и фактическое проведение занятия — только через отдельные контролируемые механизмы.

**Возможные статусы:** ready, needs_focus, safety_check_required, safety_handoff, human_review_required, paused_for_review, clinician_draft, dialogue.

Память агента не должна автоматически превращать интересы, оценки и воспоминания в диагноз. Данные из приватного профиля должны приходить только из доверенной owner-authorized серверной сессии; сервер не должен принимать access/safety флаги от клиента как доказательство. В переносимом ответе нет исходного текста, PII, сырых тестов и приватных заметок.

## Программный контракт

### Генерация программы

~~~js
import { consultPsychologistMind } from
  "../lib/holistic-support/holistic-intelligence.mjs";

const program = consultPsychologistMind({
  task: "program",
  locale: "ru",
  intent: {
    focus: "stress",
    confirmedTrigger: "criticism",
    confirmedReaction: "freeze",
    durationMinutes: 20
  },
  safety: { status: "clear" }, // утверждённый upstream-triage
  consent: { resourceImagery: false }
});
// program.status == "ready"; program.sessions.length == 8
~~~

### Общение с клиентом

~~~js
const turn = consultPsychologistMind({
  task: "dialogue",
  locale: "ru",
  intent: { focus: "stress" },
  state: { sessionNumber: 3, phase: "reflection" },
  text: "Трудно реагировать на критику",
  safety: { status: "clear" }
});
// turn.status == "dialogue";
// turn.question содержит один вопрос;
// turn.suggestedMethodIds совпадают с методами третьей сессии;
// turn.canStartExercise == false: нужен явный старт.
~~~

Фазы разговора: intake, exploration, checkin, practice_intro, reflection, next. Локализация EN/RU/ES; стиль warm/concise/structured. Текущий ответ **редакторский и детерминированный**, не LLM. При будущем подключении языковой модели она может менять только безопасную формулировку; safety, consent, method IDs и сохранение остаются за алгоритмом.

### Использование памяти по согласию

~~~js
{
  access: { authenticated: true, ownerScoped: true },
  consent: {
    profilePersonalization: true,
    agentMemory: true,
    confirmedResources: true
  },
  profile: {
    confirmedFocus: "relationships",
    confirmedResourceCodes: ["nature", "supportive_person"],
    preferredStyle: "concise"
  }
}
~~~

Текущий выбор всегда выше запомненного. Если нет доступа или согласия, память не используется. Результаты психометрических тестов пока намеренно не подключены к этому клинически чувствительному decision policy; отсутствующий показатель не заполняется догадкой.

## Интеграция с видеотерапией и клиентским кабинетом

- Каждая сессия отдаёт объективную цель, стабильные IDs утверждённых методов, язык, длительность, признак обязательной проверки перед практикой.
- Поля videoAssetId/audioAssetId остаются null, mediaPublished=false до реальной проверки прав и публикации. Ни видео, ни аудио этот алгоритм не создаёт автоматически.
- T0/T1 измеряются по одному добровольному вопросу и сравниваются **только** существующим compareVoluntaryCheckins (не причинное доказательство эффекта).
- При discomfort/worsening возвращается paused_for_review; программа приостанавливается.
- Запись истории НЕ реализована, saved=false. Для клиентской истории нужны consent, delete/export, owner RLS и E2E между двумя аккаунтами.
- Для practitioner_draft требуются реальные полномочия специалиста; даже сформированный черновик помечен publishable=false.
- Live требует серверной авторизации, ручного одобрения специалиста, сессионного UI и выполнения full e2e/production SHA.

## Тесты и контроль качества

Проверить четыре низкоинтенсивных восьмисессионных маршрута во всех трёх языках; запрет автономной KIP/EMDR/экспозиции; urgent/human handoff; отсутствие preflight; независимое согласие на образ; сохранённые предпочтения только с авторизацией; более высокий приоритет нового запроса; отсутствие утечек; паузу при ухудшении; одинаковые методы между plan/dialogue; T0/T1 без заявления об эффективности.

**Методологические ориентиры:** NICE NG116, VA/DoD PTSD CPG 2023, SAMHSA trauma-informed care, методические материалы KIP/DGKIP. Решение о клинической применимости всегда принимает квалифицированный специалист. Разработка кода сама по себе не устанавливает клиническую эффективность.

Дополнительно диалоговый модуль распознаёт явные просьбы остановиться, сообщения «стало хуже», неопределённость и вопрос «почему?». При stop он возвращает client_paused, при ухудшении — paused_for_review; упражнение не запускается автоматически.

**Уточнение practitioner draft:** для отдельных сессий выводятся clinicianDiscussionIds (например, kip_clinical, psychodynamic_interpretation), но они не попадают в выполняемые methodIds; clinicianMethodsRunnableByAI=false. Для trauma_support выдаётся отдельный список specialistDiscussionOptions (CPT/EMDR/exposure) **без привязки к сессиям**: выбор требует клинической оценки, самостоятельная травма-фокусированная процедура не запускается.
