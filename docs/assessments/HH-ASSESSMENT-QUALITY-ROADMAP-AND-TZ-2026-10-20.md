# Holistic House · Программа повышения качества тестов и чек-инов
**Техническое задание (ТЗ) v1.0 · 20 октября 2026**  
**Репозиторий:** `andylitvinov-design/books` · **Источник истины:** зарегистрированные определения `data/assessments` и `lib/assessments`, issue [#1223](https://github.com/andylitvinov-design/books/issues/1223), [PR #1297](https://github.com/andylitvinov-design/books/pull/1297).  
**Тип изменений:** безопасные изменения представления/аналитики сейчас; новые содержательные версии опросников — только после независимой проверки.  
**Принцип:** улучшение вычислительной корректности ≠ доказанная психометрическая валидность.

## 1. Цели и измеримые результаты

1. Каждая активная методика имеет **паспорт источника и качества** на точную версию, язык вопросов, целевую аудиторию, назначение, статус разрешений и отдельную оценку доказательств; отсутствие исследования отображается явно, а не как 0% точности.
2. Чек-ины дают раздельные наблюдения: **затруднения / доступные ресурсы / выполнение повседневных дел / контекст и динамика**. Нет арифметического общего «здоровья», диагноза по авторским шкалам или уверенности, вычисленной из суммы баллов.
3. Все 73 авторские семьи получают **построчный экспертный лист проверки вопросов**; P0=11, P1=2, P2=60 — приоритет пересмотра, а не научный рейтинг.
4. Клиент видит простое объяснение собственных ответов, конкретный вопрос об обстоятельствах и добровольный следующий шаг, без выдуманных причин, лечения и лекарственных назначений.
5. Старые ответы и отчёты читаемы в прежней версии; новая редакция вопроса/шкалы **не обновляет существующее определение**, а создаёт новую неизменяемую регистрацию.

## 2. Исходные факты (проверено в коде)

- 150 активных ключей: 77 опубликованных-source методик, 64 авторских поведенческих/ситуативных, 9 традиционных/типологических. Для **0** методик в локальном реестре имеются независимо утверждённые рейтинги доказательности точной версии/языка A–D. Публикация первоисточника не равна независимому одобрению нашей реализации.
- В системе есть контроль UUID/SHA, идентичности скорера, обратных ключей, достижимого диапазона, сравнимости результатов, языка, даты и ограничений выдачи. Проверка 18.10 включала 230 исторических регистраций/417 измерений, позднее добавлены 5 опубликованных английских методик.
- Исторический [PR #1211](https://github.com/andylitvinov-design/books/pull/1211) уже слит: разделение шкал, защищённая история повторных измерений, честное отображение одноэлементных оценок, реестры проверки 73 семей/137 настроенных EN-шкал.
- Текущий [PR #1297](https://github.com/andylitvinov-design/books/pull/1297): доказательные группы, убирание механического +7/+3 за «professional», осторожная сводка чек-инов; полный CI испытывает независимые сбои в других модулях, поэтому production-версия пока не подтверждена.

## 3. Роли, права и научные категории

| Сущность | Использование | Запрещено |
| --- | --- | --- |
| `reviewed_exact_edition` | Только при утверждённом обзоре научной литературы **конкретной** версии, языка, аудитории и скоринга | Путать с клиническим разрешением или гарантией диагностической точности |
| `published_source_pending` | Исходные опубликованные шкалы с неоконченным локальным обзором | Присваивать высокий балл валидности за DOI/название «professional» |
| `author_self_reflection` | 64 HH авторские наблюдательные шкалы | Нормативные процентили, диагноз, суммарный индекс психического здоровья |
| `symbolic_typology` | 9 традиционных/типологических рефлексивных методик | Медицинский вывод или заявленная лечебная эффективность |
| `reference_only` | Неактивные источники/лицензируемые исследования | Включать цифровое прохождение без законных прав |

Отдельно от доказательности учитывать `rightsStatus`, требования к квалификации, возраст, противопоказания и обработку кризисных ситуаций. Бейдж типа «из источника» не повышает validity score. Для авторских методик карточка **«Не валидировано независимо»** обязательна.

## 4. Структура паспорта методики

Новые записи формировать **только из проверенных источников**, неизменяемо относительно ключа `(key, version, respondentLocale, targetPopulation, intendedUse)`. Проект структуры (сначала в файле метаданных, без записи данных клиентов):

```json
{
  "key": "hh-weekly-pulse",
  "version": "v1",
  "respondentLocale": "ru",
  "targetPopulation": "adult/general/unspecified",
  "intendedUse": "non-diagnostic self-observation",
  "scorerVersion": "v1",
  "contentHash": "<actual registered SHA>",
  "rightsStatus": "cleared",
  "evidenceGroup": "author_self_reflection",
  "review": {
    "content": "pending",
    "cognitiveInterviews": "pending",
    "languageAdaptation": "pending",
    "reliability": "not_established",
    "responsiveness": "not_established",
    "independentApproval": false
  },
  "sourceEvidence": []
}
```

Поле `contentHash` брать из зарегистрированного определения, не из черновика. Никакого «100%» на основании контрольной суммы. Любое одобрение научной валидности привязывать к исследованиям с методологией, целевой популяцией, языком, редакцией, корректностью ключей, а не к одному PDF.

## 5. ТЗ: точные чек-ины и анкеты

### 5.1 Current State: редакция-кандидат v3
Период: **сейчас**, ответы 0–10 по каждому пункту, явно подписаны оба полюса.
1. Основная трудность; 2. Внутреннее напряжение; 3. Физическая усталость; 4. Силы для одного маленького дела; 5. Ощущаемая поддержка; 6. Насколько трудность мешает планам сегодня.  
**Не объединять «силы и внутреннюю опору»**. Для 6-го пункта — отдельное `not_applicable` при отсутствии соответствующей ситуации (не числовой 0). `state.resource` v2 **не сопоставим** ни с энергией, ни с поддержкой v3.

### 5.2 Weekly Wellbeing: редакция-кандидат v2
Период **последние 7 дней**, раздельные наблюдения: эмоциональное состояние; внутреннее напряжение; трудноуправляемое беспокойство; нагрузка; восстановление после сна; восстановление после отдыха; доступная энергия; ясность мышления; связь с людьми; ощущение поддержки; участие в повседневных делах.  
Один ответ относится к одному конструкту. Не объявлять 11 вопросов одной латентной шкалой, не вычислять общую альфу или «вылеченность». Контекст: «Была ли неделя необычной?», «Что помогало?»; контекст текстовый, не участвует в формуле. «Нет такой ситуации» не равно «0».

### 5.3 Felt Safety / Body–Mind Context
Опираться на файл `author-tool-content-revision-candidates-2026-10-18.md`. Для Felt Safety отдельные подпоказатели **телесное наблюдение / доступный комфорт / границы и выбор**, без общего среднего. Для Body–Mind Context разделить **ощущения / обстоятельства / функционирование**; знания о медицинской помощи не суммировать с симптомами и никогда не делать вывод о физической причине. Элементы, не подходящие ситуации, исключаются с сохранением статуса missing/applicability, не нулём. Порог полноты каждой предполагаемой 3-пунктной подшкалы — минимум 2 применимых ответа, **только после экспертного утверждения**.

### 5.4 Quick и Detailed
- **Quick 20–40 сек:** несколько одиночных прямых оценок. Явно *не эквивалент* полной версии, не заменяет исследовательский опросник.
- **Detailed 1–3 мин:** больше независимых показателей + добровольный контекст + возможность «Не было такой ситуации».
- Значение `mode` записывать отдельно от формы; для разных составов вопросов **не строить общие временные ряды** и не переименовывать v1/v2.

### 5.5 Словарь вопросов
Каждый вопрос должен иметь `itemId, construct, recallPeriod, language, min, max, anchorMin, anchorMax, polarity, isOptional, applicabilityRule, sourceVersion`.  
Контроль: одно понятие на вопрос, нейтральный язык, отсутствие «и/или»-двойных измерений (исключение — необходимая по смыслу пара после экспертной проверки), доступность на iPhone/экранном дикторе, отсутствие внушения причины/лечения. Лингвистический автоматический флаг — **только кандидат на рецензию**.

## 6. ТЗ: анализ клиента и отображение результата

**Контракт анализа (только после `verifiedHistoryResult`):**
- `observation`: точное имя и 0–10/1–5 значение каждого показателя; период/язык/версия.
- `difficulty`: трудности отдельно; высокий ответ **не** превращать в клиническую тяжесть.
- `resource`: явно указанные ресурсы отдельно; низкий ресурс **не** является доказанным дефицитом личности.
- `function`: повседневная жизнь независимо от интенсивности проблемы и ресурсов.
- `context`: конкретная ситуация, неоднозначность недели, необязательное свободное описание; **никакой автоматической постановки диагноза по тексту**.
- `comparison`: два подтверждённых идентичных источника/языка/периода; delta = новая оценка − предыдущая. Без изученной ошибки измерения — **арифметическая разница, не доказанное улучшение**.
- `reflectionQuestion`: один уважительный контекстный вопрос, выбранный из ограниченного шаблонного словаря; исключить необоснованную причинность и лечебные предписания.
- `qualityNote`: «Авторская описательная шкала, независимая валидация точной версии отсутствует». Текст для опубликованных шкал отличается.
- `sourceMissing`: если хеш, версия, диапазон или ответы недостоверны — не показывать персональный вывод, не подменять более старой записью.

**Пример (искусственные данные):** «Напряжение 8/10, ощущение поддержки 3/10, влияние на дела 4/10. Это разные ответы, не общий индекс тревожности. В какой ситуации возникало напряжение и что делало его легче?». Не делать вывод «поддержки мало, поэтому тревога».

**Профиль/кабинет:** группировать отдельные графики и компактные карточки по категории; для новых версий начинать новый baseline, архив старых показывать в отдельном периоде. PDF, экранный отчёт и история должны использовать общие источники и подписи. Никаких личных ответов в публичном HTML/SEO.

## 7. ТЗ: реестр валидности и контроль качества

**Этап QA0 — машинные проверки (автоматизируем):** проверка существующего каталога и контрольных хешей, диапазонов, обратных ключей, 100% item-to-scale coverage, прав, точной версии, скрытия исследовательских материалов. Генерация *ревизионного* реестра 73 авторских семейств и всех EN/RU вопросов без персональных данных. Подозрения «двойной вопрос», неконсистентный период, полюса, N/A — **не итог экспертной оценки**.

**Этап QA1 — рецензирование содержания (человек):** минимум независимых двух рецензентов на семейство/подшкалу; документировать релевантность, полноту, ясность, возраст, культурный контекст и необходимость каждого пункта. Разногласия фиксировать, а не скрывать усреднением.

**Этап QA2 — когнитивные интервью (с согласием):** опрашивать людей, соответствующих целевому языку и аудитории, наблюдать понимание каждого вопроса и якорей. EN/RU отдельно, ES только после самостоятельной адаптации. Версии текста фиксировать; отрицательные отзывы сохранять как дефекты, не подгонять статистику.

**Этап QA3 — выборочные исследования:** согласованная исследовательская программа и объём выборки под каждую цель. Для предполагаемых отражающих многопунктных шкал — размерность, омега/альфа с CI после проверки предпосылок, воспроизводимость и ошибки; для единичных/формирующих чек-инов — адекватность содержания/интерпретируемость, повторяемость при сопоставимых условиях, чувствительность и внешние якоря. **Не вычислять alpha для 1 пункта**. Не строить пороги автоматически из распределения клиентов.

**Этап QA4 — доказательная оценка:** независимо проверенные публикации по точной версии, языку и популяции, методические риски, лицензии. Любой рейтинг A–D — только после полного разбора применимых критериев. Пока реестр пуст, в каталоге показывать ожидание проверки, а не завышенную оценку.

## 8. Порядок реализации и критерии приёмки

| Этап | Изменения | Автоматизируется? | Приёмка |
| --- | --- | --- | --- |
| P0. Реестр | 150 инструментов, группы 0/77/64/9, обновляемый внутренний аудит | Да | Для каждого ключа ровно одна группа; без фиктивных A–D |
| P1. Каталог | Фильтр EN/RU/ES, убрать бонусы по типу, сохранить релевантность темы | Да | Нет бонусов +7 и +3; источник не повышает `matchPercent` |
| P2. Анализ | Чек-ин: трудности, опоры, дела и контекст — отдельно | Да | На одних и тех же фиктивных ответах одинаковая EN/RU семантика, без диагноза |
| P3. Ревизионный аудит | Проверка всех авторских вопросов, якорей, источника и направленности | Да (предварительный) | Item ledger покрывает все EN/RU исходные вопросы; замечания `needs_review` |
| P4. Новые формы | v3 Current, v2 Weekly, отдельные формулы N/A | **Нет**, сначала проверка | Экспертное утверждение содержания + когнитивные интервью |
| P5. Пилот | Независимая оценка качества измерений | Нет | Протокол согласия, план статистики, отчёт с ограничениями |
| P6. Релиз | Versioned DB + iPhone/EN/RU/PDF/privacy/rollback | После P4–5 | Все обязательные адресные тесты и exact-SHA Vercel READY |

**Нефункциональные требования:** отчёт не даёт автоматических назначений лекарств и гарантий; исходные ответы приватны; guest-выбор не запускает тест без клика; исследования не читают Client Cabinet без отдельного явного согласия; нет новой тяжёлой зависимости/постоянных CRON/дорогого KV-сканирования; доступность клавиатурой и экранным диктором; нулевая запись/миграция частных результатов без QA.

**CI:** отдельно запустить `psychometric-validity-directory`, `checkin-scoring-analysis-quality`, `professional-test-expansion-2026`, `public-test-match-paging`, `full-assessment-library-quality`; затем общий npm test/build, iPhone/screenreader, PostgreSQL, приватный кабинет и PDF. **Провал общей базы из-за независимых модулей фиксировать отдельно**, но не маркировать весь релиз live. Перед merge проверить конфликты и exact SHA Vercel.
