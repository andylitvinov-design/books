# Holistic House — complete questionnaire database audit
**Review date:** 18 October 2026 · **Technical source:** production PostgreSQL read-only snapshot + pinned GitHub `codex/public-book-library`. No client assessment responses, runs, accounts or patient records were read or changed.

## Scope — genuinely all installed questionnaires

- **145 runnable method keys**, with **230 immutable registered versions** (150 EN and 80 RU). By primary registration key: **73 original Holistic House educational/self-reflection tools**, **72 published-source candidates**; this is **not** 72 scientifically certified instruments or an unlimited commercial rights clearance.
- **80 paired EN/RU version families** were structurally compared. No differences in assigned source question IDs, integer response bounds, scorer dimension keys/items/reverse rules and scoring methods. This says nothing about the quality or psychometric equivalence of translated wording. **No third-language (ES) questionnaire was in the registered scale-source inventory**; a Spanish UI or translated result is not a validated Spanish administration.
- **417 registered JSON scoring dimensions**: **296 means**, **95 sums**, **21 direct values**, **2 ASRS shaded-response counts**, **1 official CFPB lookup**, **1 capped sum**, **1 derived Healthy Days measure**.
- **2,466 registered source question instances** (including versions/translations); **2,072 source-item-to-scale assignments** (including intentional shared items), **224 reverse-coded assignments**. **Zero** references to unknown question IDs, duplicated per-dimension item IDs, duplicated source question IDs, empty scoring dimensions, absent scoring bounds or mismatches between theoretical source item min/max and declared scale min/max.
- **219 definitions have an explicit dimension array**; **11 other versions** use dedicated scorers (Bach v1/v2 EN/RU, Current State v1/v2 EN/RU, Weekly Pulse EN/RU, Mini-IPIP EN). Dedicated scorers are not incorrectly labeled as incomplete configured scoring.
- **6 unscored functional-impairment questions in one ITQ adult version** are intentional extra impact/context items, not omitted symptom-scale items. Source items overlap across total and subscales in **11 forms** (e.g. PHQ-4, PCL-5, MHC-SF, ITQ, MSPSS, resources and compassion). **128 question instances occur in more than one dimension by design**; do not remove valid shared items.
- Every saved exact questionnaire row has a well-formed `sha256:` content hash. Registered version IDs/hashes must match the source model, and **1,380 EN/RU immutable interpretation rows** over **230 source versions**, with three versions (2026-10-17.v1, v2, v3), remain present and correctly hashed. SQL audit was **SELECT-only**. Private results not inspected.

## Concrete defect found and repaired

**CFPB short Financial Well-Being:** The published 2017 age-mode lookup contains **56 distinct attainable score values from 19 through 90**, out of the nominal 0–100 reporting scale. Previous source-aware score verification accepted *any integer* in 0–100 on its fallback path when the signed DB interpretation payload was not present. Therefore an integer such as `99` could look mathematically in-range while **not generated by any age group, mode or response total in the actual CFPB table**. The database's immutable v3 row already listed the 56 correct values; those rows have not been rewritten.

The full EN/RU report also distinguishes the **nominal 0–100 score format** from the **56 actually obtainable 19–90 official short-form values** without inventing clinical cutoffs. The application fallback now accepts a score as CFPB only if it belongs to the exact **official immutable table** and the saved dimension and provenance match the registered scorer. Other in-range but impossible integers fail verification, cannot be used in historical trend dashboards, cannot create a reassuring gauge, and return an unverified report. All 84 legitimate lookup cells (21 raw totals × 4 age/mode groups) still pass. This does not infer age, individual answers or income from a saved total.

## Automated full-library acceptance and negative tests

`tests/full-assessment-library-quality.test.mjs` audits **every** immutable definition, not a named sample:
1. Canonical SHA-256 identity, unique definition IDs and version keys; exact match of all 145 active Test Explorer entries to a registered definition.
2. Valid numeric integer response endpoints, number of answer anchors and nonempty question text for each source question.
3. For each scoring dimension: valid method, unique valid question IDs, official reverse-item subsets, direct-item polarity metadata, and exact min/max computed from each input item's original range and scorer multiplier/aggregation.
4. Explicit exceptions for known shared total/subscale content and for the six ITQ contextual items. Exceptions are *named*, not used to waive all scoring consistency.
5. The 80 EN/RU pairs retain exactly the same question IDs/order, answer bounds, scoring method and reverse keys. Translation validity is a separate assessment.
6. Each registered source can score genuine minimum/maximum synthetic answers without altering them; verification must accept the canonical scorer output. The 73 originals stay **descriptive**, and source-published thresholds only apply when directly documented for that exact form/version.
7. `tests/cfpb-attainable-result-integrity.test.mjs` tests all 84 official CFPB cells and rejects **all 45 impossible integers between 0 and 100** through the report, gauge, and history-verification consumers.

## Research-only sources and licensing guard

The active scored instruments are intentionally distinct from unadministered research references. The 15 priority source-method references (8 marked `permission_required`, 6 `rights_review`, 1 `open_reuse`) remain metadata, not runnable questionnaires. Automated checks assert that rights-gated priorities are not registered as active scorers and that professional scale PDF resources have `educational_scale_guide_only` content instead of protected test forms. Source metadata on its own cannot enable commercial test administration.

## Scientific/clinical and usage-rights boundaries

These tests prove **source arithmetic and computational invariants**, not content validity, internal consistency, measurement reliability, cross-cultural fairness, diagnosis or expected treatment response. Per COSMIN, evaluate each *score/subscale* for item relevance, completeness and comprehensibility before structural, test–retest and measurement-error validation. Professional reviewer and respondent cognitive interviews are necessary. All 73 author tools remain exploratory/non-diagnostic. The 72 published-source candidates still require exact-form evidence, target-population and language checks, verified source permissions and appropriate cutoffs. Historic versions remain immutable, including six mixed-polarity v1 forms now neutral and current v2 split scorers.

We have **not** automatically altered proprietary or clinically validated item wording, threshold tables, reverse coding, user records or historical interpretation hashes to make automated tests pass. Data supplied by the client is never a research validation sample without explicit consent.
