## Confirmed defects and this code repair

- **Two confirmed misleading directions:** `hh-approval-pressure` low answers were described as little “Pressure to Be Liked”, although the six positively keyed items measure keeping personal choice under approval pressure. `hh-goal-obstacles` named obstacles rather than the ability to recognise them and plan a step. The answer notes now use the already-audited scored construct. All 98 active answer-guide test/scale pairs are tested at actual scored extremes. Across 44 keys, note names differed from the classifier construct; the other 42 are consistency repairs, not 42 additional proven inversions. Split money-pressure difficulty and coping remain separate.
- **Bach v2:** the 38 canonical scale summaries previously substituted flower names into generic text. They now reuse the existing bilingual emotional-theme titles and reflection steps, explain weighted score position, and distinguish zero endorsement from absence of experience. They do not claim remedy efficacy, prescribe essences or introduce clinical severity. The richer full Bach report already had theme-specific evidence and follow-up; it is preserved. A necessary half-point score-lattice guard rejects impossible arbitrary decimals, without claiming every half-point is attainable for every theme.
- **TIPI:** existing lower/upper trait descriptions remain. Each of the 13 attainable means now states its arithmetic position on 1–7. The numerical midpoint is not a validated cutoff, population norm, percentile or “balanced personality”; opposing item responses can produce the same mean as neutral responses. All five traits, reverse scoring and both report locales are tested. This is still a very brief two-item-per-trait estimate, using the registered English questionnaire.

- **Thirty additional trait scales:** five IPIP50 and 25 original HH DISC, Enneagram, Socionics and temperament scales now reuse their existing instrument-specific full-report explanations and describe arithmetic sum position. Tests generate all 2,174 attainable keyed sum/locale cases across nine forms. Existing reverse scoring, emotional-stability polarity, reflection steps and cautious whole-profile hypotheses are preserved. A low score does not establish an opposite trait, and multiple tendencies can coexist. The English IPIP50 questionnaire is not relabelled as a validated Russian form. Compact/full report summaries retain the position explanation without duplicating the shared guidance.

**Thirteen direct ratings:** the five active current-state and eight weekly-pulse dimensions copy a single 0–10 answer. Their old generic sum/agreement/aggregate wording was inaccurate. New prose uses exact localized question anchors and describes one chosen answer and its reference period. The historical current-state v1 uses identical keyed question semantics, so its five scales are corrected too. Tests cover all 792 score/report-locale cases across six registered forms, including history. The resource-pulse six-item aggregate remains a genuine mean and is not relabelled as a single response. Its six separate value dimensions are single-statement ratings: a final keyed-method check found their inherited aggregate caveat inaccurate. These six now quote the exact localized statement and identify one response, without inventing questionnaire endpoints. All 264 statement/score/report-locale cases are tested; the existing numeric-position reading is preserved.

An exhaustive offline comparison covered **33,100 allowed score/locale models**. Semantic prose changes affect 30,856 models, 412 existing record identities and 123 active keys after preserving the newer owner-approved descriptive numeric readings and response-anchor fields. Before that reconciliation, the narrower semantic repairs affected 12,284 models, 124 records and 53 active keys. All eventual v2 payload hashes will change because their version and source provenance change, even where prose is unchanged. This comparison does not create or approve new database records.

## Remaining gaps and intentional limits

No summary, meaning or label was empty. Structural coverage is not evidence that every explanation is sufficiently useful, clinically validated or correctly rendered in production.

- The active inventory has 1,036 scale-record instances: 618 continuous, 392 original answer-guide and 26 source-category instances. These repeat questionnaire/report locales; there are 328 distinct active test/scale pairs.
- The 618 continuous instances cover 219 distinct test/scale pairs across 77 tests and have invariant summary text across their domains in v1. Of those pairs, 122 use one complete template, while 97 vary endpoint/interior actions. The invariant-text flag was reviewed semantically; it is not itself proof of an error or permission to invent clinical bands.
- Among the original 219 continuous pairs, 73 receive reviewed position-specific additions (38 Bach, five TIPI, 30 other traits). All remaining 146 pairs across 70 keys were then reviewed in both languages: 19 confirmed wording defects are repaired (13 anchored direct ratings and six single-statement resource ratings); 127 retain existing construct-specific continuous explanations. [The 146-pair rationale CSV](./interpretation-continuous-review-20261017.csv) records each decision, source module, range and immutable v1 evidence. Its quoted summaries/actions are historical audit evidence, not proposed v2 output. Hosted rendering and broader expert validation remain open.
- The retained 127 pairs comprise 71 authored trait/pole explanations, 11 literal health ratings/day counts, three CBI contextual scores, three symptom-frequency scores, one CFPB calibrated score, six compassion/self-compassion dimensions, two ERQ strategies, eight original HH statement/mean reflections, 13 trauma domains, four positive-wellbeing dimensions and five support/self-esteem dimensions. Exact per-pair rationales are in the CSV. Existing construct, scoring direction, time period, item grouping, endpoint labels or concrete reflection already supply useful meaning; a constant source template can still render the actual score or day count. No additional confirmed missing or incorrect interpretation was found in this source review. This does not establish clinical validity or make every continuous score a category.
- PCL-5 and ITQ intentionally have empty generic actions in 26 scale-record instances. Dedicated trauma reports carry observation/support follow-up. This safety choice must not be filled with generic treatment advice.
- **GAD-7 RU remains limited:** its Russian questionnaire version is descriptive here. English source categories are not transferred to it, and no validated Russian translation or cutoff claim is added. Reporting in Russian for the exact English form is a different case.

## Version and release gates

The combined patch preserves the newer PR849 questionnaire endpoint fields and compact-report UI. Its generic arithmetic reading remains for other descriptive scales; reviewed Bach/TIPI/trait prose avoids duplicating position paragraphs. Direct ratings retain both actual endpoints and explicit single-answer context. The exporter now captures all eight numeric context interpolations, including the newly added score-reading text.

This patch selects stored interpretation `2026-10-17.v2` and rules `2026-10-17.v12`. Current consumers reject v1 and missing/stale rules versions, including old v10 prose relabelled as v2. They use verified exact-provenance code fallback when no approved v2 record is available. UI source labels remain honest about that fallback.

The original 460 records, approved digest map, seed and release descriptor stay immutable as historical receipts. Native integration checks continue to prove their hashes, provenance, locale coverage, RLS, immutability and explicit historical reading. The current-runtime test additionally proves that this v1-only database yields code fallback. **That is not native PostgreSQL v2 parity or a database-complete v2 release.**

A database-backed v2 release requires, in order:

1. Commit and verify the exact repaired source tree.
2. Export 460 new v2 records from that commit against the unchanged technical definitions; exhaustively verify finite-domain rendering and semantic boundaries.
3. Independently review the new payload digests, source proof and INSERT-only package. Preserve old identities and stop on conflict. Assess exact authorization for the interpretation-table inserts separately; an older payload approval does not approve changed prose.
4. Exercise v2 in isolated native PostgreSQL with the approved digest allowlist, loader, security and mismatch tests. Only then publish the new approved digest/release artifacts and apply the authorized new records with readback.
5. Verify hosted checks and actual rendered synthetic reports before claiming the repair is live. Complete hosted/expert review separately; the public-count difference is reconciled above.

At this package stage the implementation and tests are local, new v2 database records are not generated or approved, and production rendering is not certified. The audit does not claim all 145 tests have been semantically perfected.
