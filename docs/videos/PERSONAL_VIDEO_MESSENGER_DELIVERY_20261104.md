# HH Personal Video → Telegram / WhatsApp · v1 · 2026-11-04

## Scope and confirmed baseline
Production branch: `codex/public-book-library`. Existing Video Studio exports an actual user-owned MP4/WebM Blob **locally in the browser** after playback validation. It does not silently upload source photos or personal wishes. Current private MP4 archive is `app_private.personal_videos` / Supabase private bucket `hh-client-private-media` (guard `HH_PERSONAL_VIDEO_CLOUD_SAVE_ENABLED`), max **12 MB/file, 3 videos/account, 180 MB global**. Existing client Telegram /start pairing, signed webhook, owner-scoped encrypted chat IDs and private message alerts are reused; CRM WhatsApp identifiers are *not* verified client media destinations.

## UX (EN / RU / ES)
1. Only after a playable real result, **Save video / Скачать видео** opens an inline chooser: save directly to device; share the current file via device Share menu (choose **Telegram** or **WhatsApp**). The old direct-file fallback and preview remain available. A Web Share API dispatch is a **user-initiated app share**, not an automated bot send or proof of which app was chosen.
2. Typing **«скачать ролик»**, «отправить ролик», `download video`, `enviar vídeo` in the completed Video Director chat opens the **same** chooser (not a second renderer).
3. Signed-in user can **connect the already configured Telegram bot** using a one-time 15-minute /start challenge, verified only by existing signed webhook. An OAuth/Telegram login or typed username is never proof of chat ownership. Existing service-alert topics are preserved, not silently turned on.
4. Signed-in and linked user can explicitly send one MP4 **via the verified bot** after consenting to cloud upload. User may separately opt in to **automatic future sends**, and may turn it off. Re-linking requires reconsent because the stored chat hash and precise `verified_at` must match.
5. Guest users can save/share locally. The interface links to existing Cabinet account settings for bot verification. No auto enrollment, recipient guessing, marketing, CRM merge or news subscription.

## Processing and constraints
- Each new locally playable MP4 (10/15/20/30/60 seconds, ≤12 MB) uses existing signed private upload: (a) authenticated intent, (b) upload to private bucket, (c) owner-scoped server verification of actual bytes, MIME and MP4 `ftyp`, (d) private owner delivery claim, (e) server-side download from private storage, (f) Bot API `sendVideo` multipart bytes with **server-only** bot token. MP4 contains the final visual output; raw prompt/photo isn't uploaded separately.
- Delivery read/write requires verified Supabase session, active account and same-origin writes, backend RLS, per-user rate and explicit consent. A database unique key `video_id` means **one send attempt per saved video**. Recheck verified chat/hash/timestamp and preference just before sending; signed URLs and chat IDs never enter external message bodies.
- Status `accepted` means Telegram Bot API accepted the request, **not delivered/read**. A timeout is `unknown`, never auto-retried, to prevent duplicate messages.
- No new bot, bucket, scheduled worker, paid service or mass storage acquisition. Telegram delivery requires `HH_CLIENT_TG_LINK_ENABLED`, validated dedicated/shared bot credentials and the existing signed webhook. Generic `HH_CLIENT_TG_SEND_APPROVED` is **not required or changed**: the video-specific consent and release flag must not enable unrelated messages or CRM notifications. New independent guard **`HH_VIDEO_TELEGRAM_DELIVERY_ENABLED=true`** is **OFF by default**. Private Cloud Save guard must be **ON** to use bot send.
- **WhatsApp v1 supports native/manual file share only**. Automatic WhatsApp Business delivery is not activated: it requires separate official Meta Cloud API recipient verification, user opt-in, template/session policy, approved sending credentials and possible provider costs. Do not invent the user's personal WhatsApp account, send to a public link, claim automation, or use unofficial bots.
- Auto delivery is **best-effort under existing free storage quotas**. If the private bucket is disabled/full, or output is WebM/too large, keep local save/share and show a meaningful failure. This is *not* unconditional guaranteed delivery for unlimited future generated videos. Do not raise global quotas or enable paid tiers without separate approval.

## Scoped live-activation correction

The separate `HH_CLIENT_TG_SEND_APPROVED` stays untouched/OFF. Already-opted-in customers can disable their automatic video preference even when the video provider is paused. New subscriptions require explicit consent. No real provider delivery is claimed without an actual opted-in chat and media receipt.


## Private Cabinet follow-up (5 Nov 2026)
The private My Videos library provides its own Telegram pairing and status panel, explicit automatic-video opt-in and opt-out, and a one-click consented send for each previously saved ready MP4. The owner may revoke delivery even when the video sender is disabled, or the bot is unlinked. A re-linked chat must be authorized again. The provider claim is single-shot per MP4 and consent/link is checked again after private download, before the Bot API send.

Cabinet labels now include Spanish as well as English and Russian. WhatsApp is limited to user-initiated device sharing; live Meta Business credentials and recipient verification are not configured, and no paid sending has been enabled. Storage remains at 12 MB/file and 3 videos/account; no videos are erased without the owner choosing to do so. Manually imported cabinet videos require one-click Telegram delivery and are not silently auto-sent. Delivery is not proven until an opted-in user verifies a real MP4 in their own chat.


## Future-only consent and iPhone file-sharing guard (6 November 2026)
The Video Studio result distinguishes a **previously authorized** automatic Telegram delivery from a new opt-in made beside an already completed result. Consent enabled on the current result authorizes *subsequent* generated MP4s only. Sending the current result remains a separate, explicitly clicked action. An attempted permission change suspends the current result's automatic path even when the network operation fails. Each new completed result mounts a separate permission snapshot. The iPhone native Share control handles exceptions in `File`, `navigator.canShare` and `navigator.share` gracefully while keeping the explicit local-download action available. These are behavior and regression-test changes, not evidence of a real Telegram media receipt. WhatsApp Business auto-delivery still requires independent verified Meta sender, recipient opt-in and billing approval.
