# Holistic House — original motion library: 320 H.264 MP4s

## Scope and truthfulness

This is a **second, independently identified source class** alongside the existing 44 approved/licensed camera/composited videos. It supplies original **non-photographic, procedural motion art** made with Pillow + FFmpeg, not 320 newly filmed or AI-generated photorealistic scenes.

- MyTube editorial source: four categories × four subcategories × four topics = **64 topics**.
- Five visual variants per topic = **320 distinct generated video files**, each five seconds long.
- Four unique MP4s per new montage = **64 ready-to-edit original-animation film presets** after verified import.
- Export: exactly the existing four-shot video director; no new AI API, client-data upload, paid subscription or renderer.
- Retain the existing **44** licensed MP4s separately. If and only if all 320 are physically present and the protected release succeeds, the combined video source library has **364 MP4s**. Count actual files, not metadata titles or pending footage URLs.
- New 320 visual sources are 432×768 pixels at 18 fps, optimized for mobile. **Do not advertise them as native Full HD or stock photography.** 8 visual motif families, procedural seed variation, cinematic gradients, and colour palettes are symbolic treatments. Further individually filmed HD clips will be a separate acquisition program.

## Physical gate — no silent publication

1. Builder runs once on feature branch `codex/original-motion-320-20261103` and creates real H.264 MP4 + JPG file pairs under `public/videos/holistic-house/original-motion-v1/`, together with `data/video-catalog/original-motion-scenes-v1.json`.
2. A 320/320 success requires actual FFprobe H.264/duration/dimensions, decoded frame movement, byte-level SHA-256 for every master, unique master hashes, JPG poster and an overall 65 MiB budget. If the tool fails, **do not publish a placeholder manifest**.
3. Integrate only the verified media subtree and full manifest onto the existing director feature branch; retain branch history and all original stock.
4. `node --test tests/original-motion-library.test.mjs` verifies all 320 physical files match their records and can be selected in four distinct shots without arbitrary external links. `node scripts/audit-hh-video-library.mjs --strict` reports licensed vs original counts separately.
5. Existing Core/Mandala/Browser tests, iPhone Safari real video preview/export with audio, protected merge into `codex/public-book-library`, and Vercel production SHA + READY confirmation remain mandatory.

## Risk and economy

Each generated video is different byte content but related stylistically; do not equate variation with 320 wholly independent filming locations. Do not preload hundreds of videos; load covers first and prime only chosen sources on user action. Keep temporary PNG frames out of git. The workflow only operates on the one isolated feature branch and uses standard public repository CI. Building hundreds of files may increase normal GitHub/Vercel storage/bandwidth; no claims of unlimited free capacity.
